## Overview

把根 `CLAUDE.md` 的两条产品心法改成可执行的双路线流程：默认先从现象与规律创造解法，允许用低成本伸手实验产生证据；补丁型保留原有外部凑合证据标准；两路线在开枪前共同接受行为证据、失效标志与用户裁决约束。随后最小同步开发指南和用户级记忆，完成场景回放、评审与化简。

本计划只修改流程文档与记忆摘要，不生成候选、不执行实验、不触碰产品代码或状态。

## Architecture Decisions

1. **修订两条，不新增第三条**：双路线是现行「解决真实需求 + 用户想象力有限」的操作化，避免历史条款棘轮复发。
2. **证据分路线，开枪闸统一**：创造型无需预凑社区三证，补丁型保留 ≥3 来源；任何路线都不能免需求验证开枪。
3. **创造链必须到「解法重构」**：只写需求方向不够；写不出结构变化可退回补丁型，不借创造名义豁免证据。
4. **实验只定义记录契约，不定义统一数值**：通过线 / 失效线按候选预注册；具体实验仍需用户逐项批准。
5. **权威源先行，外围最小同步**：先改根 `CLAUDE.md`，再同步 `PRODUCT-DEV-GUIDE.md` 与记忆；历史选型卷不清洗、不追溯重判。
6. **根目录无 git 可用 diff**：根文件采用精确 Edit 替换并保留诊断卷中的原文引用；仓内文档仍用 git diff 检查，不创建额外备份垃圾文件。

## Verification Strategy

- **结构检索**：两条路线、默认创造优先、创造链、实验预注册、共同开枪闸、分路线调研均可定位。
- **场景回放**：逐条执行 spec §8.2 的五场景，结果写入任务清单；不接受只写「符合直觉」。
- **保持性检查**：执行纪律四项、历史条款废除状态、已埋 / 暂停产品状态均不变。
- **机器检查**：

```bash
git -C F:/github/farm01/danqing diff --check
git -C F:/github/farm01/danqing status --short
grep -n -E "创造型路线|补丁型路线|假设可以先于答案|伸手实验|创造型专项" F:/github/farm01/CLAUDE.md
grep -n -E "产品心法|创造型|补丁型" F:/github/farm01/PRODUCT-DEV-GUIDE.md
```

- **无代码测试声明**：没有 `.rs`、Cargo 配置或可执行逻辑变更，不运行 cargo 三件套；原因记入验收记录。
- **人工终审**：用户确认最终权威条款准确表达「创造优先、证据可生成、开枪不降级」。

## Risks and Mitigations

| 风险 | 影响 | 缓解 |
|---|---|---|
| 把创造型写成免验证 | 自嗨方案可直接开枪 | T1 共同开枪闸 + T5「惊艳但无人伸手」场景强制不通过 |
| ≥3 来源仍被读成全路线前置 | 创造型继续形同虚设 | 将阈值放进补丁型小节；记忆摘要同步；T5 专项检索 |
| 「默认创造」变成数量配额 | 编造现象、为创新而创新 | 明确允许本轮零创造候选；补丁型证据强可直接做 |
| 「卧槽」复活灵魂论 | 主观情感重新成为普适闸门 | 限定为创造型解法质量目标，明确非需求 / 付费证据 |
| 实验措辞被解释为自动授权 | 未经批准对外联系或发布 | 根指南与 spec 均保留逐项用户批准，T5 检查授权边界 |
| 记忆继续传播旧通用三证 | 后续会话回退 | T4 只更新现行摘要与索引，历史段明确归档 |
| 评审 / 化简扩大范围 | 回头改候选或发布闸 | T6 / T7 文件边界锁死，新增想法记 Deferred，不顺手实施 |

## Parallelization Opportunities

- T3 与 T4 技术上可并行，但都依赖 T1 / T2 的最终措辞；本任务规模小，顺序执行更省上下文。
- 评审可用独立 reviewer agent；主 agent 不同时自审同一结论，等评审结果后再修复。
- 根指南两处修改有顺序依赖，不并行写同一文件。
