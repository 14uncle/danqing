# Implementation Plan: round10 选型复审

## Overview

按 `danqing/docs/specs/round10-selection-guide-2026-10-20.md` 的三道闸门（Gate 1 agent 吃不掉 → Gate 2 需求真实 → Gate 3 陌生人掏钱），串行复审三批既有弹药：存量待判两件、round9 幸存者、0→1 六案。产出复审台账；有候选则补调研三闸，零候选则写请示。**全程零产品代码、零 git 提交。**

## Architecture Decisions

1. **串行复审，不并行堆证据**：一条走完 Gate 1→2→3 再下一条。理由是 Gate 1 就判死大半，提前收集后续证据是浪费。
2. **已有研究文档是第一证据源**：round9 深卷、0→1 六案卷、redteam 卷已含大量带日期证据；复审只做增量查证，不重挖。避免把复审拖成第二轮调研。
3. **单台账文件**：所有结论汇总到 `danqing/docs/intent/round10-rescreen-2026-10-20.md`，不分散成多卷。
4. **存量两件只出建议**：dropshelf / luoban 的「继续 / 埋掉」由用户裁决，复审不自动执行处置。
5. **去重先于复审**：A1 体裁 = luoban；物格同时出现在 round9 与 0→1 卷——只审一次，台账「来源」列注明全部出处。
6. **零候选不放闸**：复审结束若零候选，写「是否开新域扫描」请示，等用户裁决。
7. **任务即台账行**：本 plan 的每个 Task 对应台账里若干行，验收标准就是「行完整、带日期、可复核」。

## Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| 复审变成第二轮调研，无限膨胀 | 高 | 已有文档为第一证据源；只查增量；单条时间失控即记录并跳过 |
| Gate 2 证据凑不齐 | 中 | 判「证据不足」而非硬判活；写入台账「后续」列 |
| Gate 1 判得过松（什么都活） | 高 | 用四个校准样例自检：luoban 死、dropshelf / clipboard / loglens 活 |
| Gate 1 判得过严（全死） | 中 | 全死时复核「B 做不好」是否被误读为「做得出就死」 |
| 时间盒（1 个工作会话）超时 | 中 | 记录已完成条目，请示续期；不硬拖 |
| 存量两件处置被当成自动执行 | 中 | Checkpoint 1 强制人工裁决 |

## Open Questions

4. 时间盒默认 1 个工作会话；超时请示。
