## 卡 A:文件暂存架(Drop Shelf / 拖拽暂存区)

### 1. 需求一句话
跨多个文件夹收文件(邮件附件 / U 盘 / 归档 / 聊天发送)时,需要一个「中转暂存架」:从各处丢进架上,最后一次性拖出到目的地——替代多开资源管理器窗口互相拖。

### 2. 谁在凑合
**Windows 桌面用户**(需要从多处收文件发出去的人:发邮件、拷 U 盘、整理交付物、发聊天文件)。

凑合行为(出生故事里的行为描述,非言词抱怨):

- **多开资源管理器窗口互相拖**:Holdem README:「Moving files on Windows means juggling Explorer windows, losing your drag mid-way, or dropping things on the Desktop "for now".」
  https://github.com/iamzubin/holdem (建仓 2024-09-29,152★)
- **同款行为的第二种表述**:Bucket README:「Ever opened five File Explorer windows just to gather a handful of files? … One file is on your Desktop. Another is in Downloads. … Now you're dragging files between windows, trying not to drop them in the wrong place. Halfway through, you forget which window is the destination. … We've all accepted this workflow. We shouldn't have to.」
  https://github.com/aungkokomm/Bucket (建仓 2026-06-20,14★)
- **把文件丢到桌面「暂时放着」** = 土法仪式(日后再找 / 日后再挪),Holdem 出生故事点名。
- **给邻近品掏钱(Windows 侧)**:Dropshelf(微软商店 `9MZPC6P14L7N`,免费层 + Pro)用户在 issue 里自报版本号带 Pro:
  - 2025-04-29「DropShelf Pro ++」 https://github.com/williamckha/dropshelf-repo/issues
  - 2025-09-23「Move instead of Copy does not work when using the Files app」
  - 2026-01-12「Bug: Unable to change shortcut keys」
  - 2026-05-17「auto delete」— 版本「1.0.10.0 pro」
  - 2026-05-29「The last "e" on the "Drop items here" message is clipped」— 版本「Version 1.0.10.0 Pro」
  (5 例独立 issue 自报 Pro,分布 2025-04 → 2026-05 跨 13 个月,均为 `williamckha/dropshelf-repo` issue 区原生 bug/feature 帖)
- **Mac 侧同形态付费行为自白**:Bucket README:「On Mac, people happily pay for tools like **Yoink** or **Dropover**. On Windows, it's a different story—some paid tools exist but with very limited functionality, while most free ones are outdated. So I built one myself.」
- **手搓品自己承认要打的是付费层**:Holdem README:「No paywall, no wait timers — unlike Dropshelf free tier or macOS-only Dropover.」

**手搓出生证明簇(同一形态、多仓独立出现 = 绕道行为被固化)**:

### 3. 证据强度
- **来源数**:≥6 个独立仓库(Holdem / Bucket / ghost-drop / shelf / omarchy-ledge / PyDrop)+ 1 个 Windows 商店在位者 issue 区(Dropshelf)+ Mac 付费工具生态声明 — **≥3 独立来源满足**。
- **行为证据类型**:①手搓成品本身(绕道固化)②issue 里的付费自白(自报 Pro 版本号)③出生故事里的凑合行为白描(多开窗口 / 丢桌面)。**不是言词抱怨帖**,是行为痕迹。
- **付费证据单列**:
  - **Windows 侧形态对位付费 = 硬**:Dropshelf Pro 用户自报 5 例(2025-04-29 / 2025-09-23 / 2026-01-12 / 2026-05-17 / 2026-05-29)。这钱是为「拖拽暂存架」形态掏的——**形态侧对位成立**。
  - **Mac 侧形态对位付费 = 中(第二方转述)**:Bucket 称 Mac 用户「happily pay for Yoink/Dropover」;Holdem 称 Dropover 为「macOS-only」付费。App Store 直连取证失败(见局限),未拿到商店价格页 JSON-LD,故 Mac 侧记「转述 + 知名度」不记「第一方价格实证」。
  - **买断自白 > 捐赠 > 标价**:Dropshelf 商店页显示 `displayPrice: Free`(免费层),Pro 为应用内升级——用户 issue 自报「Pro」= **买断/升级行为**,强于标价。
- **需求温度日期分布**:付费自白 2025-04 → 2026-05 跨 13 个月;手搓建仓 2024-09 → 2026-08 持续;Dropshelf issue 活跃至 2026-10-05(最新 feature request)。**增量新仓仍在出现(2026-06/07/08 三连)→ 温度=活**。

### 4. 需求温度
**活**。增量证据:2026-06 Bucket / 2026-07 ghost-drop / 2026-08 omarchy-ledge 三个月三仓独立上马;Dropshelf issue 至 2026-10 仍有新帖。不是老票多新票无。

### 5. 推断链(心法二)
- **现象**:同形态小工具 2024-26 多人独立手搓 + Windows 付费在位者(Dropshelf Pro)有真实买家 + Mac 同形态工具收钱。
- **本质**:「跨目录收文件 → 一次性吐出」是 Windows 原生缺的一环。资源管理器是「浏览/移动」模型,不是「暂存/合流」模型;拖拽跨窗口在物理上就容易断。
- **什么在变**:①邮件/IM 发送文件仍是日常动作,文件来源越碎(桌面/下载/截图/多盘);②Mac 付费工具证明形态有支付意愿,Windows 侧免费层差(Dropshelf 免费层有 wait timer);③vibe-code 让「手搓一个」成本暴降 → 扎堆出生本身就是需求信号。
- **方向**:Windows 单文件/便携 GUI 暂存架(多桶/彩色分组/只存指针不动文件),免费层即获客 + 可走买断 Pro(对位 Dropshelf Pro)。
- **断环**:Mac 侧 Yoink/Dropover 的**第一方销售数据**未拿到(转述级);「谁」目前以「Windows 发件人」为主画像,再窄一层(设计师/行政/学生?)未分层。

### 6. 失效标志
- Dropshelf 官方若宣布年活用户 <1k 或停止 Pro 变现(=形态侧付费被证伪);
- 2026-10 后连续 6 个月无新暂存架工具出现且 Holdem/Bucket 停更(issue 零新增)= 热度死;
- Windows 本体/资源管理器上线「拖拽暂存区」或 PowerToys 出同名模块(系统吸收兑现);
- 调研发现 Windows 免费在位者(如 DropIt、Direct Folders)其实覆盖同形态且活跃维护 → 「免费不行」前提崩。

### 7. 载体一句话
Windows 桌面单文件/便携 GUI 可为性高:悬浮置顶小窗 + OLE 拖拽 + 指针暂存(不动文件本体),danqing 引擎可承载(Holdem 用 Tauri 证实了轻量可行)。

### 8. 判定
**立案(呈裁决)**。付费/形态侧对位硬(Dropshelf Pro 5 例付费自白 + Mac 同形态收钱)+ 手搓出生簇 6 仓 + 凑合行为白描具体。本轮座次主序=付费对位,卡 A 居首。
**早筛透镜记入**:
- 系统吸收距离:Windows 原生无暂存架,离 checkbox 远(不会像剪贴板被 Win+V 接走);但资源管理器插件是半威胁。18 个月内被顺手做掉概率:低。
- AI 需求迁移:收文件发文件仍是人类动作,增量未被 AI 工作流接走(反而 AI 生成文件更多)。
- 免费在位者:Dropshelf 有免费层但带 wait timer(Holdem 点名);DropIt 是规则引擎不是暂存架。**免费层薄 ≠ 封死**。
- 付费证据日期分布:2025-04~2026-05 跨 13 个月,非僵尸。

## 卡 B:无边框窗口(Borderless Gaming 免费版消失)

### 1. 需求一句话
游戏/窗口无边框全屏(免 alt-tab 断流)在 Borderless Gaming 转付费后,Windows 免费侧缺可靠工具。

### 2. 谁在凑合
- **Windows 玩家/多任务用户**:原用 Borderless Gaming 免费版 → 该产品转 Steam 付费、GitHub 免费二进制被删 → 自己手搓。
- ihateborders README 原文:「This project was created as a free and open-source alternative to Borderless Gaming by Codeusa, which became a paid application on Steam and **had all free release binaries removed from GitHub**.」(建仓 2025-06-28,93★)
- **已实证「免费二进制被删」**:`gh api repos/Codeusa/Borderless-Gaming/releases` 最近三版(9.6.0 / 10.1.0-steam / 10.0-steam)assets 数组全空(2024-08~2025-09),与 README 声明一致。
- 手搓簇:ihateborders(2025-06,93★)、GoBorderless(2025-02,74★)、fullscreener(2026-08)、Venipa/Borderless(2026-08)、kevin-courbet/borderless-gaming(2025-12)、FocusFrame(2024-10)。

### 3. 证据强度
- 来源数:6+ 仓库手搓 + Borderless Gaming 官方仓 releases 实证。行为证据=手搓 + 免费资源被撤(旧用户的「被遗弃」型绕道)。
- **付费证据**:无新付费自白(Borderless Gaming 本身的 Steam 销量未取证)。形态侧付费对位弱——钱是给「无边框」还是给「游戏兼容」不清楚。
- 日期分布:手搓建仓 2024-10→2026-08,但新仓星数走低(93→74→4→13)。

### 4. 需求温度
**衰减中**。现代游戏普遍内置 borderless fullscreen;手搓品自成免费在位者(ihateborders/GoBorderless 已是免费可用)。

### 5. 推断链
现象(免费版消失→手搓簇)→ 本质(无边框是游戏体验刚需)→ 什么在变(游戏引擎把它做成标配 + Windows 窗口化改进)→ 方向(增量用户被游戏内选项接走)。**断环**:「谁还在凑合」的新证据不足——2026 新仓更像惯性模仿,不是新痛点。

### 6. 失效标志(已兑现两条中的一条)
- 游戏内置无边框成为标配(已大量兑现);
- ihateborders/GoBorderless 自己成为活跃免费在位者(已兑现)。

### 7. 载体一句话
单文件 GUI 可为(挂窗口样式 WS_CAPTION),技术简单——正因为简单才挤满手搓品。

### 8. 判定
**毙**。出生故事硬(免费二进制被删有官方仓实证)但「谁还在凑合」的新行为证据薄;系统吸收距离近(游戏设置一个 checkbox);免费在位者=手搓品自己。死因=需求衰减 + 系统吸收 + 免费在位者。

## 卡 C:熄屏不锁屏(吾爱熄屏 WuAiScreenOff)

### 1. 需求一句话
一键把屏幕熄掉但**不锁电脑、不休眠**:后台下载/渲染/挂机继续跑,唤醒直回桌面不用输密码。

### 2. 谁在凑合
- 吾爱破解(52pojie.cn)场景用户:挂着下载/渲染/远程时想黑屏省电但不想锁屏。工具页:https://github.com/steen889/WuAiScreenOff (建仓 2026-06-10,61★,README 自述来自吾爱破解帖 tid=2111561)
- 凑合行为白描**缺失**:README 只写「和系统"锁屏"不同」,没写「我之前用 XX 凑合」。推断的凑合=用电源计划「关闭显示器」(几分钟延迟)或 Win+L(会被锁)。

### 3. 证据强度
- 来源数:1 仓 + 1 论坛帖(52pojie),<3 独立来源。行为证据薄(产品存在≠凑合行为)。
- 付费证据:无。纯免费工具,无形态侧付费对位。
- 日期:2026-06 单点。

### 4. 需求温度
无法判定(样本不足)。

### 5. 推断链
现象(有人做这个工具)→ 本质(Windows 无「只关屏」一键)→ 断环:什么在变/方向均无证据。**推理链 2 环即断**。

### 6. 失效标志
写得出但已被提前兑现:Windows 电源设置「关闭显示器」+ 自定义快捷方式就能做(网上教程成堆);PowerToys Awake 管「不睡眠」;系统吸收距离=一个 checkbox / 一个快捷方式。

### 7. 载体一句话
单文件 .NET 可为(本工具即证),技术门槛极低→需求门槛也低。

### 8. 判定
**毙**。出生故事薄(无「之前怎么凑合」)、来源 <3、无付费、系统吸收距离近。死因=凑合链厚度不足 + 系统已半覆盖。

## 卡 D:迷你打印机 PC 端(TiMini Print)

### 3. 证据强度

- 付费证据:作者另有商业 App(timiniprint.com / Google Play)= 对面有人掏钱,但掏的是「移动 App 解锁更多机型」,**不是 PC 桌面形态付费**。形态侧对位不成立。

### 4. 需求温度
活但窄。硬件日抛 + 机型碎片化(私有协议逐个逆向)。

### 5. 推断链
现象(有人为打印机写桌面端)→ 本质(厂商只做 App 不做桌面)→ 什么在变(不明)→ 方向(不明)。断环多。

### 6. 失效标志
- 厂商下场做官方桌面端(Phomemo 已部分有);- 该仓 star/issue 归零。

### 7. 载体一句话
单文件 GUI 可为,但蓝牙协议逆向是重活,不适合 danqing 单人带宽快速长。

### 8. 判定
**毙**。说不清「谁」的规模(硬件持有者中想在 PC 打的子集),形态侧付费不对位。死因=人群太窄 + 付费不对位。
