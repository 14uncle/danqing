## 一、题目书（interview-me 确认稿）

- **Outcome**：再开一轮产品筛选，目标是筛出一个 **agent 时代的「懒人税」产品**——用户本可以让 agent 自己做出来，但要花时间、要审美、可能半途放弃，所以宁愿买现成的。
- **User**：钱的落点是十四叔自己——农场是主业之外的缓冲地带，对冲工资单点故障；产品的用户是**有真实需求、但不会或不愿意用 agent 自己造的人**。
- **Why now**：四件产品实测下来——pomodoro 没下载、dropshelf / luoban 编码完一次没跑、loglens 只有小量 star 和下载；选型本身反复论证、越选越累，现有候选没有一个过得了「agent 吃不掉」这条。
- **Success**：筛出的候选同时满足三条，**按此优先级**：
  1. **agent 吃不掉**——不是技术上做不到，是用户不会自己动手做
  2. **需求真实**——现在还有人在凑合
  3. **有陌生人掏钱**——不是 star，不是下载量

  （原第 3 条「出品有保证」2026-10-20 用户裁决**丢弃**，见第三节。）
- **Constraint**：单人、业余时间、引擎复用（danqing）、载体默认 **Windows 桌面 + 买断**；钱必须重要，但不能用「够大」把「agent 吃不掉」挤下去。
- **Out of scope**：照指南排名靠前就开工（dropshelf / luoban 的老路）；用 star / 下载量当燃料；为选型去硬开一个自己没有使用场景的新领域；把「够大」排在「agent 吃不掉」前面。

## 二、这条意图是怎么长出来的（访谈实录摘要）

1. **起点**：用户发起——「产品候选指南再开一轮，现有候选没有眼前一亮的感觉，身心疲惫」。
2. **假说一：情感基础**。由 pomodoro / loglens 的「领域不熟、没有使用场景」推出——**被用户推翻**：「可以没感情，钱很重要」。
3. **假说二：真实用户**。由 dropshelf / luoban 编码完一次没跑推出——成立但不充分：loglens 有真实用户场景（本地日志查看）仍然掉线，所以「自己是用户」不是必要条件。
4. **关键转折**：用户主动追问「agent 时代，Claude Code / WorkBuddy 是不是也能解决」「微信有自己的公众号助手，是不是能解决排版」——**「agent 吃掉」成为核心恐惧**。
5. **钉死语义**：agent 吃不掉 = **乙**——agent 做得出来，但用户不会用它的版本（不知道要找它、不敢信它、懒得装配它）。用户补一刀：*「别人用 agent 做出同样的功能，是要花时间精力审美，或许放弃，自己用现成的」*。即护城河 = **现成 + 审美 + 省事**。
6. **取舍**：「够大」与「agent 吃不掉」冲突时，用户选**「agent 吃不掉」**。

### 实测账本（判据的依据）

| 产品 | 落地状态 | 实际死因（用户实证） |
|------|----------|----------------------|
| pomodoro | 商店已上架，GitHub 无下载 | 领域不熟、无个人使用场景 |
| loglens | 有下载与小量 star | 短暂兴奋后「star / 下载只是数字」，量级小、无感情、掉线 |
| dropshelf | 机器侧全闭，**用户一次没跑过** | 无个人需求；选型指南排名产物 |
| luoban | 机器侧全闭，**用户一次没跑过** | 无个人需求；核心转换活恰好是 agent 一句话能干的 + 微信编辑器在补 |
| clipboard | **每天在用，基本替代 Ditto** | 唯一活着的——但它商业化已终止，是自用工具不是商品 |

结论：旧指南筛的是「需求真不真 / 有没有付费竞品」，不筛「用户会不会自己用 agent 造」。所以产出一水是可被 agent 一句话复刻的转换类 / 单点工具。

## 三、新判据的可操作定义

### ① agent 吃不掉（第一闸）

- 不是问「agent 能不能写这个代码」——几乎都能写。
- 要问：**目标用户拿到需求后，会不会真的去让 agent 造一个？** 拦住他的是：要描述清楚、要审美、要调试、要维护，以及造出来只有一个版本、改不动。
- 可执行问法：*「这个用户现在有 Claude Code / 豆包 / WorkBuddy，他为什么还要买？」*
- **死刑句**：核心价值 = 一次转换、一次生成、一次搬运 → 死。

### ② 需求真实

沿用现行心法：谁还在为这件事凑合？≥3 独立来源、近两年、带日期、行为证据优先于言词。

### ③ 出品有保证（2026-10-20 用户裁决：**丢弃**）

不作为筛选判据，也不设独立验收条。质量保证回落到既有的发布前闸（`PRODUCT-DEV-GUIDE.md` 发布前闸），选型阶段不再单列。

### ④ 陌生人掏钱

二值判定：有陌生人付费才算成立。star、下载量、装机量均不计。

### 「够劲爆」的处置

用户无法给出「劲爆」的具体参照画面。本卷**不把「劲爆」列为可操作判据**，其可操作替身已拆进 ①（用户不会自己造）和 ④（有人掏钱）。若日后出现具体参照物，再回填。
