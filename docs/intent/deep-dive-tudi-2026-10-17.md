### 需求衰减（云自动化/办公 agent 接走了一半）

- **已被接走**：表单流（简道云/飞书多维表格自动化）、NL 办公任务（WorkBuddy 2026-03 上线）、网页/可 API 化流程（影刀 AI WorkOS/八爪鱼 AI写流程3.0/蓝印「一句话建流程」）、文件批处理（鹰迅/核烁/WebRename）。
- **还剩**：本地烂软件（内部系统/网银插件/报税客户端/ERP 前端）+ 跨软件串联（「导出→改名→贴群」横跨 3+ 不互通软件）。
- **诚实警告**：「语义级理解（界面改版不死）」2026 已是行业叙事（影刀/八爪鱼/蓝印都在说），**不是徒弟独有**。

### 待补证（重要）

「界面一改宏就失效/坐标不对」的**痛点原话未挖到铁证**——只有等价表述（CSDN 2026-05「每一步操作都写死像教小学生」「弹窗报错就会卡住」）。该卖点挂**待补证**。

## 二、竞品与定价：两个差异化假设的判决

### ① 语义级 vs 坐标级：**成立，但表述收窄**

- 传统自动化一水儿坐标/选择器/图像三路：Power Automate 官方文档明文 "UI elements, images, or coordinates"（**非语义**）；影刀=元素捕获；按键精灵官网声称「AI 视觉与元素识别」但为营销语、无第三方抗改版验证。
- 真语义级（VLM 看屏）已在 computer-use agent 出现（AutoGLM「以多模态方式理解屏幕内容」），**但产物是云端 agent 会话，不是「本地+买断+可编辑仪式资产」**。
- **收窄后空白表述**：不许说「唯一语义自动化」（会被 agent 打脸）；说「**改版不死的本地仪式**」。

### ② 教三遍=收徒：**检索范围内无先发布**

- 录制器全是「录一遍→坐标/选择器步骤」（影刀网页录制/PAD recording/按键精灵「零门槛录制」）——**无多演示归纳、无「徒弟复述→人审改」环节**。
- 2025–26 国内新势力全是 **NL-to-flow**（WorkBuddy/蓝印/八爪鱼「一句话→流程」）——「说」范式占了「省事」心智，「示」范式空着。
- 学术 PBD 存在（机器人臂为主），桌面 GUI PBD 商业产品未检出。**残余风险**：英文 PBD 小众产品 Bing 没搜干净，spec 前补 Product Hunt/HN/GitHub 定向核验。
- **关键判定**：对手戏是「告诉 AI」，不是「录制宏」。

### 长尾域需求实证：强

按键精灵官网明文售卖 ERP/SAP/HIS/贷款场景；影刀「任何桌面应用程序包括 ERP/浏览器/CRM/微信/钉钉」；PAD 文档举「legacy applications, such as terminal emulators」+「automates data entry on an ERP system」——**在位者把目标域当卖点卖（企业价），prosumer 买断「个人收徒」位无人占**。

## 三、吸收距离：缝隙 **18 个月存活约 60%**（50–70）

### 威胁核实（对母卷三刀的修正）

1. **Power Automate「语义化录制」：公开面未落地**。实探 docs 路径 404；现状=选择器式桌面流+AI Builder(Preview)+OCR，UI 元素仍要人手 Ctrl 点选。威胁②降级，但 release planner 全文拿不到，保留暗桩可能。
2. **WorkBuddy 自动化任务 = 到点重跑一条提示词**（官方文档：标题+提示词+频率+时间），**不是「看你做三遍→学成仪式→确定性回放」**。威胁①形态错位确认。
3. **通用 computer-use：OSWorld 2.0（2026-06, arXiv 2606.29537）硬数据——前沿模型长程 GUI 二值完成率仅 20.6%**（Opus 4.8+max thinking）；败因=丢约束/漏中途信息/跳过校验——**恰好是仪式化确定性回放要解的问题**。Codex Computer Use（2026-04 上 Windows）强制前台接管、面向测试场景。live agent ≠ 可托付报税/网银。
4. **Windows：Click to Do = 单步建议动作**（内容不保存、限 Copilot+ PC），「录制我的操作」路线图未找到。

### 子功能吸收矩阵

| 子功能 | 18 个月吸收概率 | 备注 |
|---|---|---|
| 坐标级执行 | ~95%（已死） | 红海，不是可防守层 |
| **演示学习交互** | **15–25%** | 全网无大厂在售「演示 N 遍→学成可回放流程」 |
| **仪式编辑/管理（资产化）** | **15–25%** | 无人把「仪式」做一等公民资产（版本/回滚/审计/导出） |
| 语义级执行（实时 NL 控 GUI） | 45–60% | 被 UI-TARS/AutoClaw/Codex 做烂做免费——但那是「实时 agent」不是「确定性仪式回放」 |
| 长尾 GUI 适配 | 25–35% | 云 agent 被合规/前台/数据出域卡住；本地缝隙被保护 |

### 最大单一威胁（按杀伤力）

1. **【最大】字节 UI-TARS-desktop 类开源 VLM GUI Agent**（Apache 2.0 可商用+本地部署+脚本编辑器，UI-TARS-2 发布 2025-09）——免费、本地、可商用，与「本地+买断」正面撞，会把「AI 自动操作长尾软件」抢成品类默认答案。**最大敌人不是微软腾讯，是 Apache 2.0**。
2. 次席：OpenAI Codex Computer Use 下探办公用户——OSWorld 20.6%+前台限制使其 2028-04 前不太可能完成。
3. 第三：WorkBuddy 把自动化任务升级为「录制/技能捕获」——概率不高但杀伤在渠道。

### 尸体/反向证据

- 演示式自动化的下线尸体：**未找到**（也不能编造）；老牌坐标宏仍活着=坐标层红海反证。
- **腾讯 QClaw**（母卷吸收侧挖到）：桌面 AI 智能体、可接管键鼠，2026-09-24 公告停服、12-24 关服，上线仅 9 个月，行业评「通用全权限桌面智能体路线被证伪」——live agent 路线的死亡证明，利多仪式路线。
- **未闭环风险（诚实）**：PBD 空位**也可能是「前人趟过没水」**——本轮没拿到付费证据证明「个人买断型 GUI 仪式工具」有市场，需选型侧另查。

### 失效标志（吸收侧，写死）

① Power Automate 或 Windows 发布「录制我的操作→语义流程」且支持遗留 MSAA 应用；② WorkBuddy/AutoClaw 增加「看我做→存成可回放步骤」且敢跑网银/报税场景；③ OSWorld 类长程基准二值完成率突破 ~60%（live agent 逼近可托付，仪式护城河塌）。

## 四、粗算一页

- **流量基准（农场实测）**：pomodoro MS Store 首月 46 浏览/12 安装；8 渠道 ≈570 阅读→24 安装→0 付费。
- **徒弟可见面**：MS Store + 内容分发（教程/对比文对 prosumer 有效，Quicker 类人群聚集在少数社区）；受众比物格窄但付费意愿高（KM $36/Quicker pro 实证）。乐观记 100–300 有意向阅读/月。
- **转化**：prosumer 工具付费转化 2–5%（高于家用 App）。
- **月流水**：200 × 3% × ¥38 ≈ **¥230/月**；年化 <¥3k。教学成本（「教三遍」要演示视频）拉高获客成本。
- **工时**：spec+build **6–10 周**（GUI 自动化可靠性是硬骨头，比物格重）。
- **结论**：收入 ROI 同样不成立；按**资产/锻炼**记账——新引擎肌肉（OS 自动化/确定性回放/审计日志）是 danqing 从未有过的重肌肉，复用价值高但工时风险也最高。

## 五、定位修正（写进裁决前的案形）

- **卖「可托付、可审计的仪式资产」，不卖「AI 操作员」**：仪式=一等公民资产（可版本化/审计/导出/离线重放/出错可回滚/说清每一步点了什么）——这是 OSWorld 20.6% 所暴露 live agent 结构性反面，也是报税/网银/内网唯一买得安心的点。
- **一句话**：演示三遍，电脑出师——本地仪式资产，改版不死，专治无 API 的烂软件。
- **分层**：缝隙战机是现状；能翻成品类的窄门=仪式可信度（不是更聪明）。

## 七、红队记录（2026-10-17，doubt-driven 新上下文审讯）

命中要害：

1. **付费证据全在企业侧**（炮弹级）：按键精灵企业定制/影刀考证/企培全是**企业花钱**；「个人买断 GUI 仪式工具」付费证据卷内自认缺位——「养活品类」不等于「为你的产品付费」，推理被偷换。
2. **三条待补证是承重墙不是补丁**（炮弹级）：最坏面读法——「界面改版就死」的痛感=重录 5 分钟的小烦恼；个人不会为 GUI 自动化掏 ¥30（AHK 免费钉死地板）；PBD 空位=前人趟过没水。三条全断则核心卖点/市场/空位全灭。
3. **「仪式资产」被判品类错配**：版本/审计/导出是企业合规词汇，个人 prosumer 不为审计日志买断——企业需求被移植进消费者产品。
4. **缝隙战机 ≠ 母卷成功标准**：母卷 Success 要求「第一次见的交互/品类必须立住」，四刀已判师徒交互叙事被先发布夺走心智（「说」范式占位），深卷改口缝隙战机 = 降级逃逸。
5. **UI-TARS 最大威胁未进矩阵**：卷子称其「最大敌人」，矩阵里却给语义级执行的豁免条款。
6. **徒弟无内部失效标志**（全是盯大厂）。

**红队没打穿的硬处**：OSWorld 20.6% 数字为真（外部核实）、QClaw 停服为真、WorkBuddy 形态错位判断准确、「长尾软件摆渡人」切口方向对（云 agent 结构性盲区）、检索诚实。

## 八、案级裁决：**归档**（三条复活钥匙）——待用户点头生效

**依据**：需求存在性为真（土法原话+品类养活），但入场券缺口在**市场侧**——付费行为证据全部指向企业 RPA，个人买断位的「空位」可能是「没水」；且「改版不死」这一核心卖点的痛点原话无铁证。三条承重墙待补 ≈ 重做一轮调研，在证据补齐前继续投入违反心法一。

**复活钥匙（三条同时满足才回炉重审，缺一不复活）**：
1. 挖到 ≥2 条「界面改版宏失效」用户原话（带日期、独立来源），且语境是行为级（为此换工具/花钱/写脚本）；
2. 挖到 ≥1 个「个人买断 GUI 自动化」付费先例（买断制、个人向、¥20+ 档；Quicker pro 不算——它是订阅/授权不是买断对标）；
3. Product Hunt/HN/GitHub 定向核验 PBD 空位：无先发布 **且** 无「前人尸体」。

**归档后遗产保留**：OSWorld 20.6% 脚注、「仪式资产 vs live agent」的分析框架、长尾 GUI 合规盲区结论——若复活或他案用得上。
