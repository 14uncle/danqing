# round13 选型工作卷 · 2026-11-18

> 首轮跑在 2026-11-17 新规下。前情：round11/12 连续清池、卡1(DB workbench)深挖后判死、元宝 inbox 70 篇仅出 L1(搁置)。同日裁决「必须长在 danqing」硬约束→默认偏好。

## 口径（本轮规则）

- **生死判据只剩心法两条**（2026-09-25）：
  1. 「谁还在为这件事凑合？证据呢？」——凑合=绕道/手工土法/为它掏钱/给免费工具擦屁股；**言词抱怨不算、投票总数不算、「我觉得」不算**
  2. 现象起点+推理链书面+失效标志前置（没有现象的「培养」叫许愿）
- **证据门槛**：≥3 独立来源、近两年、**带日期**、看帖子创建日期分布（老票多新票无=已死）；**付费行为单列**（最强证据；抢救免费工具只证明需求在、不证明肯付钱）
- **引擎约束已降级**（2026-11-17）：不预设场域，需求在哪就在哪；形态不长在 danqing 只是不加分，不是毙掉理由
- **流程**：开放扫描（3 路 agent，75 分钟硬盒，每路 ≤5 卡宁缺毋滥）→ 候选卡 → 初判（活/死/观察）→ 活卡深挖（调研三闸：裁决段+红队+一页粗算）→ 用户裁决
- **坟头纪律**：埋掉产品（xirang/disk/tile/dropshelf/luoban/卡1 DB workbench 等）不复活；**L1 热键冲突定位器保持搁置**（复活需用户点头，本轮不自动回池）
- **扫描产出三路**：①GitHub 大流量免费工具 issues 缺口 ②海外社区求助帖+付费工具差评 ③中文社区土法/绕道帖

## 候选卡

### 路1 · GitHub 大流量免费工具 issues 缺口（2026-11-18 交卷；18+ 仓库，gh 精读正文/评论）

**卡1 · 剪贴板「复制后加工」工作流：多条目按序粘贴 + 文件粘贴为路径**
- 现象: 多条目复制后想按序批量粘贴/文件粘成路径文本，免费工具全链凑合：置顶窗反复夺焦、求绑 AutoHotkey、四条内置路全堵死后手工编辑导出文本去空格
- 谁在凑合: 表单/聊天窗口连填多字段的重度粘贴用户（客服/运营/开发）；要把复制文件批量转路径文本的开发者/文档写作者
- 证据: Ditto #1128 (2026-07-25) 置顶窗土法全流程自述「still isn't a smooth workflow」/ Ditto #1018 (2025-12-09) 求 scripting/AutoHotkey 擦屁股 / Ditto #1139 (2026-08-27) **最硬**：逐一试 4 种 workaround 全败、输出逐字符空格垃圾、手工清理「had to write it manually」/ 跨仓库 PowerToys #51342 (2026-10-15) CopyTap 三剪贴板、#41931 (2025-09-22) Win+V 粘完即关求 stay-open、老票 #17350(2022)/#3768(2020) queue+slots
- 付费信号: 无直接陈述（擦屁股行为成立）；TextExpander 类付费存在属邻域旁证
- 吸收距离: 中偏高——缺口在免费工具**内部**（Ditto 自己没做好）；PowerToys Advanced Paste 活跃演进，18 个月内微软顺手补「顺序多粘贴」概率不低
- ⚠️ **坟头边界**: clipboard 产品 2026-09-05 已终止（Win+V/Ditto 封死历史管理）；本卡缝隙在「粘贴侧加工」非历史管理，**是否与已埋判死重叠须用户裁，不许照旧复活 clipboard**
- 失效标志: Ditto 合入顺序多粘贴/路径粘贴任一（1128/1139 官方关闭），或 Win+V/Advanced Paste 上线 stay-open 多粘贴

**卡2 · 磁盘空间巡检报告：远程机器导出 CSV/JSON 慢 + 传输土法**
- 现象: IT 管理员把 WinDirStat 跑在磁盘快满的远程机上导报告传回分析，导出慢到不可用（300 万文件逐条查 ACL）、报告大到传不动；凑合 NTFS 压缩绕道、自己提 PR 加 zip
- 谁在凑合: 管多台机器磁盘空间的 IT 管理员/运维（「We run WinDirStat remotely on machines that are really low on space」）
- 证据: windirstat #759 (2026-11-08) 远程低空间机器+「transferred over the wire」+用户主动提 PR 加 zip+维护者教 NTFS compression 绕道 / #755 (2026-11-02) CSV 导出 300 万文件 ~20 万行/秒比重新扫还慢、用户自己写导出进度条原型——同月双票同场景，自成重复
- 付费信号: 不明（TreeSize/JDiskAlert 商业存在但无付费陈述）
- 吸收距离: 高——上游正吸收（PR 在审）+ Intune/SCCM 企业侧本就管
- ⚠️ **坟头边界**: danqing-disk 2026-09-15 已埋；本卡是其邻域「批量报告」切片，**复活与否仅用户可裁**
- 失效标志: WinDirStat 合入 zip 输出或 owner 列异步导出（PR/修复落地）即死

**卡3 · HDR 显示器截图色彩还原**
- 现象: HDR 常开用户截图发灰/发白，工具自带校正两头堵；硬核用户逐行读着色器代码定位 tonemapper 拐点 0.8 数学错误（纯白 1.0 被压到 224）并给修正方案——为一张截图对免费工具修到 shader 级
- 谁在凑合: Win11 + HDR 显示器常开的截图重度用户（HDR 面板普及人群在涨）
- 证据: Snipaste #3809 (2026-11-06) 官方校正发灰/关掉发白+shader 级根因定位 / #3803 (2026-10-28) 同主题一月内第二票 / ShareX #8900 (2026-10-19) f.lux 色温叠加两次=多工具色彩管理皆失准 / #3807 (2026-11-04) 标注细节票相邻
- 付费信号: 部分——Snipaste PRO 买断存在；#3811 (2026-11-12) PRO 付费用户抱怨 OCR 差（OCR 线非 HDR 线，旁证付费者仍在凑合）
- 吸收距离: 中——Windows 截图 API 平台级老大难多年未修，但 18 个月内微软顺手修 Win+Shift+S HDR 无法排除；若修，第三方全体塌方
- 失效标志: Snipaste 修好 tonemapper（3809 关闭）或 Windows 自带截图 HDR 还原正确
