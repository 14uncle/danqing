## 二、候选卡(共 5 张,全部毙)

### 卡 1:耳机- Windows 集成工具「买了但缺机型」

1. **需求一句话**:在 Windows 上无缝管理蓝牙耳机(电量弹窗/ANC 切换/入耳检测),覆盖自己那款机型。
2. **谁在凑合**:已购 MagicPods 的用户在机型换代/新买耳机后缺适配,去 issue 区排队求适配;未获支持期间只能用厂商臃肿 App(索尼 Headphones Connect / JBL / 厂商套件)或系统残缺的蓝牙电量显示。行为证据:
   - [MagicPods-Windows#443](https://github.com/steam3d/MagicPods-Windows/issues/443) 2026-02-03:「I bought this app… worth every penny」+ 求适配 AKG N5 Hybrid(付费买断 + 缺件)
   - [MagicPods-Windows#456](https://github.com/steam3d/MagicPods-Windows/issues/456) 2026-09-20:AirPods 5 识别失败、降噪不可用
   - [MagicPods-Windows#453](https://github.com/steam3d/MagicPods-Windows/issues/453) 2026-07-28:「I need help to make my JBL Vibe Buds 2 compatible」
   - [MagicPods-Windows#442](https://github.com/steam3d/MagicPods-Windows/issues/442) 2025-12-04:Dyson OnTrack
   - [MagicPods-Windows#408](https://github.com/steam3d/MagicPods-Windows/issues/408) 2024-11-06:假芯片 AirPods 3(AB1562U)
   - [MagicPods-Windows#451](https://github.com/steam3d/MagicPods-Windows/issues/451) 2026-06-20:索尼 WH-1000XM6 电量百分比问题
3. **证据强度**:6 条 issue 跨 2024-11→2026-09(连续);**付费证据 1 笔**(P1,买断自白 + worth every penny);来源实为**同一仓的 6 个用户**——算独立用户但**同一产品**;形态侧对位:**对位**(Windows 桌面托盘买断)。缺件类型=「买了但缺 Y」,座次本应最高。
4. **需求温度**:活(2026-09 仍有新机型请求)。但增量被两个方向接走:①Win11 蓝牙设备电量显示逐年完善;②各厂商 App 免费内置。
5. **推断链**:现象=付费买托盘耳机工具 + 换代后排队求适配 → 本质=蓝牙耳机协议私有、跨品牌兼容是持续工程而非一次产品 → 什么在变=耳机型号发布速度 > 单人适配速度 → 方向=**这不是单人产品,是适配劳动密集型服务**。断环:未取证到「不用 MagicPods 时拿什么凑合」的直接原话(厂商 App 推断环)。
6. **失效标志**:若 MagicPods 官方适配覆盖率达主流机型 90%+ 且系统托盘电量原生可用 → 本卡「缺机型」缺口已被吸收,记证伪。
7. **载体一句话**:Windows 桌面托盘单文件 GUI 可为(电量/ANC 控制),但**逐机型协议逆向是主要成本**,与单人带宽冲突。
8. **判定**:**毙**。依据:缺口是「在位付费产品(MagicPods)的适配劳动」,不是「无人做的产品」;心法一的「拿不出凑合=已被满足」在此适用——用户已在为邻近品(MagicPods)掏钱,补机型是给它擦屁股;系统吸收距离近(Win11 原生蓝牙电量)。付费证据仅 1 笔且未披露金额。

### 卡 2:MS Store 绑定许可的企业墙(已购无法激活)

1. **需求一句话**:在公司 PC(MS Store 被组策略禁用)上用上自己已购的商店应用。
2. **谁在凑合**:买了 MagicPods 但公司封 MS Store 的人,装得上 appx 却**无法激活许可**,到 issue 区求旁路;想买的人(2022 那条)直接被「只能走商店」劝退。行为证据:
   - [MagicPods-Windows#437](https://github.com/steam3d/MagicPods-Windows/issues/437) 2025-11-06:「I purchased in 2023… company policy blocked MSStore… not able to activate with license」(付费 + 无法用)
   - [MagicPods-Windows#229](https://github.com/steam3d/MagicPods-Windows/issues/229) 2022-07-29:「Can't Buy Outside MS Store - Corp. Policy Restriction」(**窗外**,不计入窗口,仅作同构印证)
   - 类比:[signalapp/Signal-Android#14357](https://github.com/signalapp/Signal-Android/issues/14357) 2025-10-03「Secured Backup without Play Store」——移动端同构,Play 绑定订阅想脱离商店。
3. **证据强度**:窗口内独立来源 **2**(MagicPods 付费用户 + Signal 用户)；不足 3。付费证据 1 笔(买于 2023,窗口边缘)。形态对位:桌面应用许可,但**买家其实是我们这样的卖方**(需要店外许可方案),消费端是「已购被锁」。
4. **需求温度**:活(2025-11 + 2025-10 都有)。企业 IT 政策只会更严。
5. **推断链**:现象=商店绑定许可在企业 PC 失效 → 本质=分发/许可与商店身份耦合 → 什么在变=企业锁店普遍化 + 独立开发者多渠道分发 → 方向=店外许可激活(文件 key / 独立账号)成刚需。断环:未取证到「为此付费做许可系统的买方」;Paddle/Keygen 等在位者已供店外许可。
6. **失效标志**:若主流商店应用都已提供店外激活且用户不再抱怨 → 缺口已闭。
7. **载体一句话**:许可激活器/独立 license 文件对桌面应用可为,但这是**卖方基础设施**不是终端用户工具。
8. **判定**:**毙**。依据:窗口内来源不足 3;形态侧买家错位(开发者/厂商,不是桌面 GUI 消费者);Paddle/Keygen/Lemon Squeezy 免费在位;且我们自己的 log 付费层本就要走店外许可——那是工程问题不是选型。

### 卡 3:桌面应用许可生命周期坑(激活数/取消/收据/标价)

1. **需求一句话**:买断或订阅一个桌面小工具后,能换机、能查收据、能取消、价格页与结算页一致。
2. **谁在凑合**:Pluely(macOS Tauri 会议 AI 助手,2720★)与 mailflare(邮件 SaaS)的付费用户在 license 丢邮件 / 激活上限 / 取消无门 / 标价跳变里打转,发 issue 求厂商修。行为证据:
   - [pluely#313](https://github.com/iamsrikanthnani/pluely/issues/313) 2026-10-08:买 dev-pro 后上传文件仍提示无 pro(权益 bug)
   - [pluely#307](https://github.com/iamsrikanthnani/pluely/issues/307) 2026-09-09:收据未达 → 无法取消 → 订阅持续扣费;App 内无账单 UI
   - [pluely#284](https://github.com/iamsrikanthnani/pluely/issues/284) 2026-07-23:换机触发「activation limit」,双机都不能激活
   - [pluely#299](https://github.com/iamsrikanthnani/pluely/issues/299) 2026-08-18:Lemon Squeezy URL Invalid
   - [mailflare#96](https://github.com/hieunc229/mailflare/issues/96) 2026-10-08:$19→$29 标价跳变 + PayPal 后无 key
3. **证据强度**:5 条,但**独立产品仅 2 个**(Pluely 4 条 = 同一产品售后);付费行为硬(P3 $29 PayPal、P4 买断、P5 订阅续费)。形态对位:**弱**——Pluely 是 AI 会议助手(macOS),mailflare 是邮件 SaaS;都不是「Windows 桌面 GUI 工具」的缺口。
4. **需求温度**:活(2026-10 仍有)。但这痛是「已购工具的售后质量」,不是「缺一个工具」。
5. **推断链**:现象=付费后许可链路断(邮件/激活/取消) → 本质=独立开发者自建许可易碎,MoR 兜底不完整 → 什么在变=买断制独立工具增多 + 邮件可靠性下降 → 方向=许可管理是卖方卫生问题。断环:没有证据说明用户会为「许可管理器」这个独立工具掏钱。
6. **失效标志**:若 Lemon Squeezy/Paddle 全面提供「license key 即账号」的取消/迁移入口,痛点消失。
7. **载体一句话**:桌面 license 管理器可为,但用户预期这是**购买的软件自带**,不是第三个 App。
8. **判定**:**毙**。依据:①独立来源不足(Pluely 单产品);②形态错位 + c+ AI 对话挂钟邻域(Pluely=会议 AI 助手);③这是卖方售后卫生,拿不出「有人为缺一个许可工具而凑合」;④免费在位者(MoR 平台)正在补。

8. **判定**:**毙**。1 来源;形态错位;利基社群政治工具,与产品线无关。
