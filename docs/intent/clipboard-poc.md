## 一句话

第二件产品的岗位不是市场征服, 是「引擎复用验证器」——证明 danqing 服务第二件产品时边际成本趋零; 「打磨引擎」寄生其中, POC 完成之日 = 引擎痛点清单清零之时。

## 已确认的意图 (restate, 2026-08-13 用户显式 yes)

- **结局 (Outcome)**: 剪贴板历史管理器 POC, 验证 danqing 服务第二件产品的边际成本趋零
- **用户 (User)**: 你自己是第一个用户; 然后是被 Ditto/CopyQ 糙感劝退、认丹青审美的人
- **为什么是现在 (Why now)**: pomodoro 免费闭环走完 (零反馈也是信息: 产品没问题, 是传播功夫); 引擎需要第二个真实消费者逼出缺口。一份带宽转两台复利机器: POC 推进 = 引擎打磨清单生成与清零
- **成功 (Success)**: POC 走通四块引擎新肌肉 + 效率工具族「克制版氛围」设计首验 + 引擎复用率可量化 (共享多少代码 / 新增多少 / 改了多少框架 API)
- **约束 (Constraint)**: 单人带宽; 十年尺度最小结构, 不做大而全; 数据格式第一天为十年设计, 且剪贴板含密码——隐私正面设计 (排除/加密/清空策略), 不是事后补
- **不做 (Out of scope)**: 付费门禁、数据同步后端、macOS/Linux 打磨、功能细节边界 (搜索/收藏/格式支持——留给 spec 阶段)

## 引擎验证的四块新肌肉

1. **剪贴板监听** (arboard 已在依赖, 但只用于写入, 监听是新模式)
2. **扫读密集型列表 UI** (Scrollable 首次实战; 效率工具族高频调用场景)
3. **全局唤起 + 粘贴注入** (hotkey/foreground 已有基础, 粘贴注入是新平台工作)
4. **高频调用下的按需渲染** (M2 省电遗留, 番茄钟的持续渲染模式不成立)

## 选型记录 (为什么不是电子木鱼)

| 考察项 | 剪贴板 | 电子木鱼 |
|--------|--------|----------|
| 引擎新肌肉 | 四块 (见上) | ≈零 (音频/动画/场景番茄钟全验过) |
| 设计系统 | 首验第二族「克制版氛围」 | 第一族美学复读 |
| 数据复利 | 剪贴板历史极黏 (隐私须正面设计) | 功德计数, 薄 |
| 变现 | 弱但有史 (效率工具有付费意愿) | ≈零 |
| 成本 | 中 (数周) | 极低 (数天) |
| 传播性 | 平 | 强 (meme 品类) |

木鱼的否决理由: 对引擎复利零贡献 (做完第三件产品成本不降); meme 受众 ≠ 效率工具受众 ≠ 未来付费用户, 反馈信号是噪音。零反馈根因是渠道运营功夫, 不是产品数量——不用战术勤奋掩盖战略问题。木鱼的最佳归宿是周末小品, 不是产品线。

第三选项考察过并否决: 启动器 (scope 大 + utools/Wox 红海)、便签 (引擎覆盖面不如剪贴板)、呼吸/白噪音 (同族相残蚕食番茄钟)。
