- **日期**：2026-11-18
- **上游意图**：`product-selection-guide-creative-route-2026-11-18.md`（用户已明确确认）
- **本文性质**：正式 spec 前的诊断与文字草案，不是新候选清单，不启动任何产品实验
- **诊断对象**：`farm01/CLAUDE.md`「跨仓库约定」「产品心法」及其实际执行方式

## 1. 裁决

**需要调整，但不是新增第三条选型标准。**

本次问题可以由现行两条心法自身推出：第二条已经允许从现象推断、通过培养产生需求，缺的是让它真正可执行的入口、证据时序和实验闭环。因此应做**结构与执行语义修订**，不再叠加一套平行禁令。

目标状态：

1. **创造型路线为默认先走的路**：现象 / 规律 → 第一性原理推演 → 解法重构 → 低成本伸手实验。
2. **补丁型路线继续合法**：有强烈、正在发生的凑合证据时，可以直接做，不为创新而创新。
3. **两路线共用开枪闸**：开枪前都要落到具体的人与持续行为证据；区别只在证据是查到的还是实验产生的。
4. **「卧槽」是解法质量目标，不是需求证据**：防止平庸，不替代伸手、复访或掏钱。

### 核心病根

不是「指南完全没写创新」，而是：

> **第二条给了创造合法性，第一条和调研流程却没有给创造一条能走到验证的操作路径。**

所以只加一句「要第一性原理」「要惊艳」没有用；必须改证据的**适用范围、出现时点和实验闭环**。

## 3. 修订草案：`farm01/CLAUDE.md`「产品心法」

> 以下为建议替换文本；正式措辞以 spec 裁决为准。

### 产品心法（全产品线通用 · 2026-11-18 双路线修订）

**一、做出来的东西能解决真实需求。需求证据可以查到，也可以通过实验产生。**

所有候选最终都要回答：**「谁需要它？他做了什么，而不只是说了什么？」**

但候选有两条合法路线，不能把其中一条的证据要求错套到另一条：

- **创造型路线（默认先走）**：从真实现象和底层规律出发，推导用户尚未提出的新解法。没有现成社区 issue、没有人为同类方案掏钱，**不妨碍候选入场和低成本伸手实验**；允许用实验自己产生证据。
- **补丁型路线（证据直达）**：谁还在为这件事凑合？拿出 ≥3 个独立来源、近两年、带日期的行为证据。凑合 = 绕道、手工土法、为它掏钱、给免费工具擦屁股。证据足够强时可以直接推进，不另设「必须惊艳」门槛。

两条路线在**开枪前汇合**：

- 说得清具体是谁、在什么场景、有什么持续行为；只说「我觉得」「大家都会需要」不算。
- 创造型必须有伸手实验产生的目标用户行为证据；补丁型必须有正在发生的凑合证据。
- 开枪前写死失效标志；实验的通过线与失效线必须在看结果前写下。
- 定价、渠道、竞品、模仿者是后续执行问题，不许冒充需求问题把候选否掉；真实需求证据不足也不能拿这些话题掩盖。

**二、用户想象力有限，说不出自己要什么。默认先创造解法，再从人的行为里验证，而不是先从 issues 里找产品。**

- **现象 = 行为，不是言词**：土法仪式、绕道、在错误的工具里硬扛、为邻近品掏钱，以及可直接观察的重复动作。社区和 issues 只是现象来源之一，不是需求的出生地。
- **创造链**：`现象 → 本质 → 什么在变 → 解法重构`。前三环区分事实与假设；第四环必须写出旧约束 / 旧交互如何被换掉，而不只是「更快、更美、多一个功能」。
- **假设可以先于答案，不得冒充事实**：允许第一性原理推导超出用户当前想象；不允许把未验证的推导写成已证实需求。证据可以后由实验产生，开枪不能先于验证。
- **伸手实验**：把他们想象不出的东西用最低成本放到目标用户面前，预先记录对象、接触方式、主信号、样本分母、观察窗口、通过线与失效线，再看有没有人伸手、回头、留下或掏钱。实验不是完整产品开发，不借实验自动建仓、开枪。
- **「卧槽，还能这么处理！」是创造型的解法质量目标**：追求交互或问题结构的重构，不追求表面新奇。惊叹和掌声只能记录为反应，不能单独当需求证据；最终仍看行为。
- **补丁不必羞耻，补丁式思维才需要警惕**：证据强烈的凑合可以直接修；不能因为只会查 issues，就把所有产品都做成补丁。

（历史条款全部废除的裁决不变：两道战略闸门 / 灵魂论 / 准入三问 / 缝隙三判据 / 免费例外 / 「X 但更好」死刑 / 双半验证独立条目 / 产生器体系 / 许可条款均不恢复。「卧槽」不是灵魂或感动的改名，也不是独立付费闸。）

## 4. 修订草案：`farm01/CLAUDE.md` 深调研条款

> 建议将现「选定后、spec 前必须做一轮深度调研」一条改为以下分路线口径。

- 候选进入深挖后、spec / 开枪前必须完成一轮深度调研（流程，不另立选型标准）。
- **公共项**：需求验证；现有替代与邻近付费；定价调研；系统吸收距离；裁决段；裁决前红队；一页渠道 / 转化 / 单价 / 工时粗算。
- **补丁型专项**：有明确在位者时逐条扒竞品 open issues（功能缺口、用户原话、反应数、创建日期分布）；没有在位者时如实写无，不造票。
- **创造型专项**：现象来源与日期、事实 / 假设分列的书面创造链、旧约束到新解法的结构变化、低成本伸手实验及预注册结果。没有直接竞品时研究「人现在怎样完成这件事」，不强造竞品矩阵。
- 调研产物存入 intent 文档；调研三闸仍为①裁决段②红队③粗算，缺一不进 spec。

## 5. 明确不改

- 不恢复任何已废除战略闸门、灵魂论或形态付费前置。
- 不改变引擎复用为默认偏好、组合纪律、失效标志复盘、发布埋点与 30 天校准机制。
- 不把 `PRODUCT-DEV-GUIDE.md` 的开工 / 发布闸前移到候选萌芽期；只同步必要术语和指针。
- 不规定所有创造型实验共用的样本量或转化率数字；每个候选按渠道与动作预注册，防止事后挑数。
- 不授权 agent 自行启动 POC、建仓、commit、push，不复活已埋候选，不重判历史产品。

## 6. 草案自检样例

| 输入 | 应走路线 | 正确动作 | 错误动作 |
|---|---|---|---|
| 多个近期 issue 显示用户为同一缺口写脚本、手工抢救 | 补丁型 | 核验凑合证据后直接深挖，不要求另讲一个颠覆故事 | 为了「创新」硬换交互，或只因已有免费工具就判死 |
| 观察到反复的人肉协调行为，但没人发 issue，也没有直接竞品 | 创造型 | 写创造链与结构重构，设计低成本伸手实验产生证据 | 因凑不齐三条社区来源直接杀死，或拿推演当铁证直接开工 |
| 设计者认为交互极惊艳，但目标用户没有伸手 | 创造型，未过验证 | 记录未通过，按预注册失效标志停 / 转向 | 用演示现场惊叹代替行为证据 |
| 有真实行为现象，但新解法只比旧工具快一点 | 可退回补丁型 | 按补丁型证据标准审查，不冒称创造型 | 用「第一性原理」包装普通微优化并豁免外部证据 |
