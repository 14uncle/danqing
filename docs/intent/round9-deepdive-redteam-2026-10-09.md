## 2. 成立攻击(带证据;分级=致命/可修/修辞)

### A1 · 「四合一空位仍空」是移动球门 —— **可修(降级为执行问题,不许当需求证据)**

- 卷内空位定义:「单文件便携 × 浮动置顶 × 活跃发版 × 产品化 UI」四位一体仍空。
- 对表:**StashIt**(1★,Rust+Tauri,<25MB、~4.5MB 安装包、多架 Tab、摇鼠标/热键/双击修饰键、pushed 2026-10-06)已经坐上其中 **3.5 条腿**——唯一缺口是「产品化 UI」被等同于「星数/口碑」。**DropPoint**(1094★,GPL,全链原句,winget 实测在位 `GameGodS3.DropPoint 1.2.1`)是「成熟+被验收」但重壳且 release 停 2022。**holdem**(152★,Tauri,3.1.1 2026-09-04 发版)已是「便携+活跃+全链」。
- 问题:我们 v1 上线时同样是 0 星、未经验收——**按此定义,这个座位对我们自己也是「不空之外的不可达」**。空位不是需求证据,是供给侧运气。
- 新证据(⑮):StashIt 的 winget 链接是空头广告(winget 源无包),说明连「新兵已产品化」这一层也掺水——空位叙事两侧都虚。
- **处置**:卡内删「四合一仍空」作为立案依据;留作执行定位讨论即可。

### A2 · 「缺中转暂存架」的需求表述已被免费全链证伪(心法一「已被满足」条款) —— **致命(对需求表述)**

- 心法一原文:「拿不出『还在凑合』= 需求已被满足——被系统、被免费工具、被 AI 接走都算满足,**跟有没有付费竞品无关**。」
- 事实:DropPoint 1094★(收→暂存→一次拖出**原句级**全链)+ Edge-Drop 632★(全链,MS Store 已上架)+ holdem 152★ + StashIt/KyteShelf/Bucket——**免费工具已经把这件事做完,而且不止一家**。D2 自己的结论句就是「全链已被免费覆盖」。
- 那么 2026-10 的「谁还在凑合多开资源管理器互拖」?**答案可能是:没有人在凑合那个了,他们在用 DropPoint/Edge-Drop。** 卷内凑合白描(Holdem 2024-09 / Bucket 2026-06)是**供给侧出生故事**(「所以我做了一个」),到取证日已有免费成品;Dropshelf issue 区的付费自白对着的是「买了但缺 Y」(Outlook/修饰键/文件夹监视),不是「没有暂存架」。
- 反方留活:holdem/StashIt/Bucket 本身就是「给免费工具擦屁股」行为(点名打 Dropshelf wait timer / 「free ones are outdated」),且 2026-07 仍有新买家掏钱——**「不满现有免费质量、宁可付费/手搓」这条还活着**。但这已是另一张卡:「Dropshelf 级产品化+买断的完整暂存架」,跟在位者抢,不是填空。
- **处置**:若维持立案,需求锚必须从「缺中转暂存架」重写为「买后缺件/免费品质量不足」,否则裁决段上「已被满足」一票即死。

### A3 · 幸存者偏差 + L6(1-2★ 评论正文)未挖 = 付费人群主矿没开 —— **可修(判决依赖项)**

- 122 条评分均分 4.3 ⇒ 1-2★ 必然存在(算术上不可能 122 条全 5 星还能均 4.3 而无低星)。近 7 天 2 条均分 3.0、近 30 天 3 条 3.7——**近期差于全时**,差评正集中在低星评论里。
- D1 明记 L6「MS Store 用户评论正文未拉到」;而 R1' 的补扫欠账(d 项)指定要挖的正是「MS Store 1-2★ 买了但缺 Y 差评级」。**深挖四题之一的补扫欠账仍未完成**,缺件清单目前全部来自 GitHub issue 区(79 帖)= 会写英文、会上 GitHub、有强烈不满的硬核子样本。
- 「未见退款/卸载潮」在 L6 未解前**不可证伪**——退款不留 GitHub issue。`UsageData.PurchaseCount=0` 亦说明 catalog 不追踪 IAP,「10 笔买家」只是自报下界,不能当销量。
- **处置**:裁决前必须补 L6(商店评论 API/截图取证);补不到则「无流失」「活水」两句降级为不可判定。

### A4 · Outlook 核心场景 = 付费后差评 + 未修复 + 恰是 OLE 拖拽最硬骨头 —— **可修(工时与 v1 范围,对引擎自查=重大遗漏)**

- 证据链:#61/#62(2026-02-03 pandrea-ui,Yoink 邮件上架对标)+ #77(2026-07-10 **买家**「That was because I bought Dropshelf」)。#62/#77 同症「转圈放不进」。**三帖全部 open,评论数 0**——作者从未回应。
- 技术定性:Outlook 附件不是文件路径,是 `CFSTR_FILEDESCRIPTOR`/`CFSTR_FILECONTENTS` 虚拟文件流。`WM_DROPFILES`/`HDROP` **覆盖不了**,必须实现 `IDropTarget` + 虚拟文件格式。主卷 Q4 引擎自查写「WM_DROPFILES 拖入(易)」并估「拖拽壳层 2–4 人日」——**若 v1 含邮件附件(卡上头号场景),该估计至少翻倍**,且这是 Dropshelf 做了 3 年仍坏着的地方。
- **处置**:spec 必须显式二选一——v1 含 Outlook(工时上调,拖拽壳层按 OLE 全量估)或 v1 砍掉邮件附件(则「谁在凑合」的头号人群故事塌一半)。

### A5 · Edge-Drop 触发线:新失效变体④'实质已兑现 —— **致命(对失效标志体系)/可修(对卡本体)**

- D2 自拟新变体:「DropPoint/Edge-Drop 达 ≥500★ + 活跃发版 + 全链 ⇒ 视同④类触发」。
- Edge-Drop 现况:**632★(≥500 ✓)· v0.3.2 2026-09-26(活跃 ✓)· 全链 ✓ · MS Store 已上架**——只差「同形态(浮动置顶)」一栏(它是贴边 hover)。D2 自己写「仅『同形态』一栏不满足,这是本卡最大的悬置风险」。
- 红队判:**「浮动置顶 vs 贴边 hover」是 UI 摆位差异,不是工作流差异**——用户拿到的都是收→暂存→一次拖出。拿摆位当未触发条件,与 A1 同款移动球门。**按④'的本意,Edge-Drop 已经站在触发线上,应记「实质兑现」**。
- Seelen UI 死法倒计时:Edge-Drop 若出浮动模式或把「file」提级为主关键词(其 README 已自定位 "clipboard shelf + desktop file-transfer hub"),免费在位者封死即成。且它 3 个月冲到 632★,速度快过我们从裁决到发布的任何节奏。
- **处置**:要么如实记④'已兑现(则卡按失效纪律死),要么把变体改写为可证伪的窄口径(如「Edge-Drop 出浮动窗模式」)并写进卡——**不许两头占**。

### A6 · 粗算 ≈0:「需求为真、生意为零」的又一张 c+ —— **致命(生意层);按心法不构成选型否决,但必须点破**

- 月收入期望 ≈¥0–21,工时 15–25 人日;且这是在付费对位成立的前提下算的上限。天花板价:Yoink $8.99、pomodoro add-on ¥18——买断小工具价位带就是个位数美元。
- 形态侧付费对位证明的是**品类有支付意愿**,不是**第三家进入者能分到**。钱流向 Dropshelf Pro(独占)与 Mac 双雄;我们的 0.1–0.5% 转化带是第一方实测(570→24→0 付费),贴地。
- 心法一明文:定价/渠道/竞品是执行问题,**不许在选型阶段冒充需求问题否掉**——故本条不单独构成毙卡理由;但若裁决口径含「为农场带来收入」,本卡与 c+ 同构,应如实记。

### A7 ·(修辞级)「活水」叙事压住了近评下行 —— **修辞**

- 全时 4.3 vs 近 30 天 3.7 vs 近 7 天 3.0(均2–3 条)。D1 用「不完美但值」一笔带过。样本小不足判趋势,但卷内应点明「近期新评低于全时」,而不是单方向写活水。
