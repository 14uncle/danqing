# 一个场景动效的 18 次迭代

- @author 十四叔
- @date 2026/08/01
- 状态: 草稿(待校订)

---

做场景沉浸,难的不是"动起来",而是"动得对"。

我的番茄钟有六个场景,每个场景有一段环境动效。山场景是一层暖粉融入暮色,森林场景是一层拂动的雾霭。就这两个看起来最"安静"的效果,我迭代了 18 个 commit。中间踩的坑,值得记下来。

## 坑一:wrap-clean 数学的错觉

动效要做成循环,最朴素的思路是让时间参数在某个周期内绕回。我最初给山的暖粉雾设了一个 `speed = 0.0625`,8 秒回绕一次。心想 8 × 0.0625 = 0.5,凑得挺整,回绕时画面总该接得上。

然后我看到第 8 秒处有一个 5% 的跳变。

错在哪?那层雾不是单个正弦,而是 4 个正弦的叠加,空间系数是 6、8、12、16。时间进入每个正弦时先乘了这个系数——所以 8 秒里,四个正弦各自累积了 3、4、6、8 弧度的相位。要让回绕无缝,每个都必须是 2π 的整数倍,可它们都不是。最扎眼的是第一项:`sin(3) ≈ 0.14`,离 0 差得远——回绕那一刻,四个正弦集体跳变。**"数值上凑整"和"函数上闭合"是两回事。**

正确修法是把时间从"周期回绕"换成"持续累加":直接用 `u.rain_time`,一个不停累加的 f32,25 分钟不溢出,循环性交给视觉本身的对称性,而不是数学的巧合。后来我把所有"持续漂移"类的动效都改成了这条路径,不再纠结 wrap-clean 的数学。

## 坑二:alpha 的可见度阶梯

雾这种东西,调 alpha 调到头秃。我记录了一条阶梯:

- `0.10–0.15`:不可见。用户说"看不清楚"。
- `0.20–0.30`:微妙可见。用户还是说"看不清楚"。
- `0.30–0.45`:明显可见。这才是目标区间。
- `0.45–0.55`:强势,但开始读作"一团云"。
- `≥0.55`:彻底变成"独立云团",不再是"融入暮色的雾"。

**雾的上限是 0.50,超过就破语义。** 这条经验帮我省掉了很多"再调大一点"的回合。

## 坑三:sum-of-sines 和 value noise 选错了是灾难

森林场景的雾霭,第一版用两层正弦叠加。流畅,有波纹,但问题来了:正弦有周期性,两层的公共周期会重复,于是雾像一条传送带,一眼能看出在"转圈"。

我换 value noise。没有周期了,但 cell 边界处出现可见的方块感——雾读成了马赛克。

结论是分场景:**大尺度的连续氛围(雾)选 sum-of-sines,但要错相错周期避免传送带;小颗粒(雪、碎点)选 value noise。** 没有银弹,两种噪声各有各的"指纹"。

## 坑四:遮罩宽度

雾该盖住画面多少?第一版做了 55% 屏高,弥漫得不像话;缩到 38%,聚焦了,融入了。40% 是临界点,容易读成一条"带子"。

**≤40% 为宜。** 视觉上,"融入背景"的动效宁可窄一点、专注一点。

## 最大的坑:机制错了,幅度救不回来

海场景是我交的第一笔学费。我给海面做了波光,用**亮度调制**——让某些点每隔一会儿亮一下。第一版 ±4%,不明显;加到 ±8%、±35%,用户一句话点醒我:

> "感觉是光在车顶上跑,车没动。"

对,亮度调制作用在静态图之上,人眼读作"一个明暗对象沿静态背景移动"。**幅度加码救不了错误机制。** 换用 UV 位移——扭曲采样坐标,让剪影本身起伏——一轮就通过了。

但 UV 位移也有边界。雨场景里,雨丝是沿自身轴向均匀的线条,位移它,除了丝头,沿线看不出任何变化。这一例我又试了两版机制,最后用户裁了更干净的方向:**静态图去掉烘焙的丝,运行时全程序化渲染雨幕。** 现在雨丝是程序生成的,几百根,随计时运行下落,暂停时定格。

这条教训我总结成一句选型准则:**看元素的几何。有剪影边缘可动(波带、山脊、树冠)→ 用 UV 位移;沿轴均匀的线条(雨丝)或点状粒子(余烬)→ 去烘焙,程序化渲染。**

## 18 个 commit 的耐心成本

回头看,这 18 个 commit 里,真正的问题反复只有两类:周期性和视觉语义。如果我在第 5 个 commit 时就想明白"调参调不动是因为抽象层级错了,该换函数换范式",能省一半的时间。

我现在给自己定了一条纪律:**同一个主题超过 5 个 commit 还不收敛,就停下来提级反思——不是参数的问题,是机制或范式的问题。**

场景动效是件很"软"的事,但踩坑踩出的这些硬规律——数学要真闭合、alpha 有语义上限、噪声有指纹、机制决定一切——它们比任何一帧画面都更值钱。
