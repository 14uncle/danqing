# 场景沉浸转向 —— 美学方向与 POC 顺序决策

- @author 十四叔
- @date 2026/07/23
- 状态: 已确认 (interview 流程, 用户显式 yes)

## 决策

1. **美学方向转向潮汐 (Tide, io.moreless.tide) 式场景沉浸**: 场景大图是界面主角、
   界面色调随场景流动、UI 退后极简; 玻璃表面保留为大图上的可读性层。
2. **产品分两族**, 美学剂量不同:
   - **专注陪伴工具** (番茄钟、呼吸、白噪音): 驻留久、密度低, 氛围即功能, 全量沉浸。
   - **效率工具** (剪贴板管理器、启动器、便签): 调用频繁、扫读密集, 氛围是税,
     用克制版 (低存在感场景 + 强玻璃)。
3. **首个 POC 由剪贴板历史管理器改为专注陪伴工具 (番茄钟)**: 它是设计系统的
   最佳验证器 (场景大图、动态色调、玻璃卡片、计时动画全覆盖, 范围小);
   剪贴板降为第二 POC。

## 为什么

- 用户在阶段 1 终审关闭后明确: 浅色毛玻璃"工具感太重、没有情绪",
  "阶段 1 甚至可以推倒重来"。
- 场景沉浸适合状态陪伴型工具, 不适合检索操作型工具——番茄钟是前者, 剪贴板是后者,
  故 POC 顺序对调; 两族共享同一美学方向, 只是剂量不同。
- 潮汐本身就是专注/睡眠工具, 用户是这类产品的真实用户, 有体感。

## 什么不推倒

- 框架与 widget 逻辑 (M1~M3 + 阶段 1 的 token 体系、组件 API) 全部保留;
  推倒的只是 showcase 的美学取向与背景资产。
- 分层背景管线 (gradient/glow/noise) 离"场景摄影 + 动态色调"只差一步, 顺势演进。
- 静态预渲染模糊路线不变; 不做实时全屏动态模糊。

## 悬而未决

- 浅色 / 深色最终定论 (潮汐偏暗, 待场景方向落地时定)。
- 场景图资产来源 (摄影图版权、自生成渐变场景或授权图库)。
- 动态色调提取方案 (从场景图取色算法 vs 每场景手工配色)。
- 剪贴板 POC 的"克制版氛围"具体形态。
