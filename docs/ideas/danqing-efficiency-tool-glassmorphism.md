# 丹青战略定位：Rust 效率工具的轻量自绘 UI 基础设施

> 定稿时间：2026-07-18
> 决策路径：从“通用 UI 框架 / 小游戏 UI”收敛为“效率工具优先 + 毛玻璃设计系统 + 性能基础设施”。

## Problem Statement

> **How Might We:** 如何让 丹青 从一个“功能不断生长的自绘 UI 框架”，进化成一个**有明确用户、独特视觉语言和性能背书的 Rust 效率工具 UI 基础设施**？

## Recommended Direction

**产品定位：丹青 = Rust 效率工具的轻量自绘 UI 基础设施。**

**目标用户：** 想用 Rust 写一个跨平台、小而美的效率工具的开发者——剪贴板管理器、番茄钟、启动器、便签、快捷命令面板等。

**核心叙事：**
- 比 Tauri **更轻量**（无 WebView、无 Chromium、启动快、占用低）。
- 比 egui **更适合复杂表单**（保留模式、布局系统、输入框、滚动、焦点）。
- 比 iced **更 Rust-native**（直接自绘，无抽象过度）。

**视觉语言：现代毛玻璃风（Glassmorphism）。**
- 半透明表面 + 背景模糊
- 细腻高光与柔和阴影
- 低饱和背景、高对比文字
- 大圆角、流畅动效
- **浅色模式优先**，暗色模式后续支持

**三大支柱：**
1. **效率工具优先** — 产品定位与场景。
2. **毛玻璃设计系统** — 品牌与视觉一致性。
3. **性能基础设施** — 启动速度、常驻占用、按需渲染。

## Key Assumptions to Validate

- [ ] **Rust 开发者愿意为效率工具选择 丹青 而非 Tauri/egui/iced。**
  *验证：发布 1~2 个效率工具 demo，收集社区反馈。*

- [ ] **丹青的 wgpu 自绘在启动速度和常驻占用上能赢过 Electron/Tauri。**
  *验证：做等效 demo 横向对比启动时间、内存、CPU 空闲占用。*

- [ ] **毛玻璃效果在跨平台自绘下性能可接受。**
  *验证：采用静态预渲染模糊方案，先在 1080p 下跑 60 FPS 验证。*

- [ ] **一个开发者能在 1~2 个月内用 丹青 做出可用的小工具。**
  *验证：阶段 2 完成剪贴板历史管理器并记录工时。*

## MVP Scope

### 阶段 1：设计系统 + 品牌视觉（4~6 周）

- 定义颜色 token、字体层级、间距、圆角、阴影、动效曲线。
- 实现浅色主题骨架，暗色模式接口预留。
- 设计 丹青 LOGO，导出 16/24/32/48/256 px PNG 与 Windows `.ico`。
- 实现自绘标题栏（LOGO + 标题 + 窗口控制按钮）。
- 改造现有组件（Box、Button、TextInput、TextArea、Scrollable）使用新 token。
- **交付**：showcase 呈现毛玻璃风格，窗口标题栏/任务栏/exe 图标统一。

### 阶段 2：效率工具 POC —— 剪贴板历史管理器（4~6 周）

**选择剪贴板历史管理器的理由：**
- 直接复用 丹青 现有能力：TextInput、Scrollable、剪贴板、搜索/过滤、列表。
- 能验证常驻后台、低占用、快速启动等核心卖点。
- 是效率工具里最常见、用户最熟悉的品类。

**交付**：`examples/clipboard.rs` 可运行，支持：
- 监听剪贴板变化
- 历史列表 + 搜索
- 点击条目回写剪贴板
- 毛玻璃 UI（静态预渲染模糊）

### 阶段 3：性能基础设施（4~6 周）

- 启动时间基准与优化。
- 按需渲染（damage-based），空闲时接近 0 CPU/GPU。
- 内存占用分析（字体图集、组件树、纹理）。
- 与 Tauri/Electron/egui 最小对比报告。

## Not Doing（and Why）

- **不做 HIS/医疗客户端** — 超出当前能力，硬件集成和业务组件太重。
- **不做游戏专用组件** — 与效率工具定位冲突，sprite/动画/HUD 不在此阶段。
- **不做完整通用 UI 框架** — 先服务一个明确场景，避免什么都做、什么都不精。
- **不做多窗口/系统托盘/全局热键等重度系统集成** — 阶段 2 识别真实需求后再逐步补齐，避免过早抽象。
- **不做实时全屏动态模糊（初始版本）** — 先以静态预渲染模糊实现毛玻璃视觉，性能风险可控。

## Open Questions

3. 性能对比的基准机器是什么配置？需在计划阶段确定。
