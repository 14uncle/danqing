# Spec: 番茄钟场景动效 — 雨场景改造(静态图去丝 + 程序化雨幕 + 暂停定格)

## Objective

海场景终审(2026-07-29)后,用户指示雨场景按 UV 位移范式改造("背景图也要跟着动")。本里程碑沿该指示开工,经两轮机制试错与用户两次裁定,最终落在更干净的方向:

1. **UV 位移对雨丝不成立**(试错记录,详见 Open Questions): 画中雨丝是沿自身轴向的均匀细线,沿线方向位移除丝头外无可读变化——摆动式剪切(±5px)目测"底层静态背景图的雨没有动";双相位流图(持续滑落+淡出淡入)机制可行但鬼影与速度-行程权衡复杂。用户裁定换方向:**"静态背景图雨丝去掉,运行时动态渲染雨丝"**。
2. **最终形态**: 静态雨图不烘焙雨丝(生成器去 `streaks` 重出 `rain.png`),雨 = 运行时三层程序化雨幕(试点里程碑已建),密度加码独挑(~290 丝对齐原 320 画中丝观感),雨效收敛为单一机制。
3. **暂停定格可见**(用户同日追加): "暂停也需要显示雨丝"——雨强不再随包络沉降,新增雨钟:包络只推进下落时间,暂停 500ms 减速冻结、恢复 500ms 加速续走,无跳变。海/火沉降语义不变。

剂量继承雨试点/篝火/海终审校准;雨幕密度对齐原静态图观感,丝宽保试点终审裁定的 2~3px。

用户: 番茄钟使用者(单一用户即作者本人)。成功 = 运行时雨幕下落("棒,效果对了"),暂停雨丝定格可见,不抢余光、不破性能门槛。

## Tech Stack

- Rust + wgpu 30 + winit 0.30(同主仓);雨幕全部在 `src/render/background.wgsl` 程序化生成,零新资产(反向:删了一段烘焙资产)。
- 复用既有通道: `rain_intensity` + `time` uniform、`motion.rs` 策略层、`MotionEnvelope`;新增雨钟占用 uniform 第 7 槽(原 pad0,布局仍 32B 不扩容)。

## Design

### 资产(生成器)

- `tools/export-scenes.py` 雨配置删除 `streaks` 键(注释记录裁定);`build_streaks` 函数暂留(生成器能力件,是否删除待用户裁定)。
- 重新生成: 仅 `rain.png` 变更(206KB→89KB),其余 4 场景字节不变(管线确定性);`scenes.rs` 重出无 diff(中央采样区丝太淡,不影响极值采样)。

### 雨幕独挑(background.wgsl 雨段,参数集中可调)

- 机制不变(三层分列 hash 雨丝,试点终审形态);独挑后密度加码: 有雨列门槛 0.93/0.91/0.95 → 0.70/0.72/0.85,~290 丝(144+100+48)对齐原静态图 320 画中丝观感密度;列密度 480/360/320 不动(丝宽保 2~3px),速度 0.125/0.25/0.375 不动(8s 公共周期)。

### 暂停定格(雨钟)

- `BackgroundFrame.rain_time` + `with_rain_time()`(框架能力);uniform 第 7 槽 `pad0` → `rain_time`,布局仍 32B;上传前 `wrap_motion_time` 取模(与动效时间同纪律)。
- 策略(motion.rs): `rain_intensity(from, to, fade)` 去包络 = 纯场景淡化权重;火/海 `fire_intensity`/`sea_intensity` 仍含包络不变。
- 接线(main.rs): `rain_clock += dt × motion_gain` 每 tick 推进;暂停包络 500ms 衰减 → 雨钟减速冻结,恢复加速续走;窗口隐藏无 tick 自然冻结。
- shader: `rain_overlay(in.uv, u.rain_time)`;强度 0(非雨场景)零贡献,输出与静态逐像素一致(暗启动纪律)。

## Boundaries

- **Always**: 提交前 `cargo fmt --check` + 两个 clippy + 全部测试绿 + 五轴评审;雨幕参数集中在 wgsl 雨段常量区;策略层在 example 侧纯逻辑;场景资产只经生成器改,不手改 PNG/`scenes.rs`。
- **Ask first**: 新增依赖;改性能门槛;篝火 UV 位移化(下一里程碑,另行开工);删 `build_streaks` 生成器能力件。
- **Never**: 手改 `scenes.rs`;为动效引入新资产文件;改变重绘频率(可见 60fps / 隐藏零渲染);在 widget/layout/event/text 引入平台依赖。

## Success Criteria

1. 雨场景计时运行时雨幕持续下落,帧差证据: 运行 vs 暂停差分(雨幕净贡献)mean > 0 且分布满屏;对照场景(山)同法 ≈ 0。
2. 形态与观感: 密度对齐原静态图(~300 丝),丝宽 2~3px,三层快慢纵深;剂量"一眼可见但不抢戏"(用户目测裁定)。
3. 暂停雨丝定格可见: 暂停后两帧(≥500ms 沉降完成后)帧差 ≈ 0(冻结)且截图可见雨丝;恢复从冻结点续走,无跳变(单元测试锁定)。
4. 火/海效零回归(沉降语义不变,既有测试全绿);非雨场景雨效恒 0。
5. 窗口隐藏时零渲染成本(架构事实,无新增 `request_redraw`)。
6. benchmark 门槛 PASS(暖机启动 ≤1s、常驻 WS ≤360MB)。
7. 提交门槛全绿(fmt / clippy×2 / test×2)+ 五轴评审通过。
8. 用户人工终审通过。

## Retreat Discipline

任一触发即 `git revert` 整里程碑,不留 feature flag:

- benchmark 回归(启动或内存超门槛且排除冷启动伪影后仍超);
- 终审不过且调参 >2 轮仍不达标(用户主导的方向修正不计入,同篝火"7px"、海"UV 位移"先例——本里程碑两次用户裁定均属此类);
- 五轴评审发现架构性反流。

## Open Questions

(全部已决议, 2026-07-29)

1. **UV 位移对雨是否成立**: 不成立。摆动式剪切(±5px, 2 层同向行波)目测"底层静态背景图的雨没有动"——画中丝沿自身轴向近乎平移不变,沿线往复滑动除丝头外无可读变化;流图式持续滑落(双相位三角权重交叉)机制成立但带鬼影权衡。用户裁定换方向: 静态图去丝,雨全程序化。
2. **静态图去丝后雨幕剂量**: 对齐原 320 画中丝观感密度 → 有雨列门槛 0.70/0.72/0.85 (~290 丝),丝宽/速度不动。终审 "棒,效果对了"。
3. **暂停语义**: 去丝后暂停 = 澄澈天空(初版实现),用户当日追加 "暂停也需要显示雨丝" → 雨钟定格方案(强度去包络,包络只推进下落时间)。
4. **雨钟放哪**: uniform 第 7 槽(原 pad0),32B 布局不扩容;海里程碑"第四效果继续填 pad"的既定路径首次兑现。
