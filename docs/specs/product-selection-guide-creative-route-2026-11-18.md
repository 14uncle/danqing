# Spec: 产品选型指南双路线修订 — V1

- **日期**：2026-11-18
- **状态**：已实现，用户终审通过（2026-11-18；spec / plan / build / review / code-simplify 全闭）
- **上游意图**：`danqing/docs/intent/product-selection-guide-creative-route-2026-11-18.md`（用户 explicit yes）
- **条款诊断**：`danqing/docs/intent/product-selection-guide-creative-route-diagnosis-2026-11-18.md`
- **性质**：流程与文档规格，不是产品规格；V1 不生成新候选、不执行实验、不写产品代码

## 1. Objective

把现行「两条产品心法」从容易被执行为**社区证据筛选 → 竞品缺口修补**，修订为可执行的双路线流程：

- **创造型路线为默认先走的路**：真实现象 / 底层规律 → 第一性原理创造链 → 解法重构 → 低成本伸手实验 → 行为证据。
- **补丁型路线保留**：正在发生的凑合行为已有强证据时，可直接深挖和推进，不为创新而创新。
- **两路线共用开枪闸**：开枪前必须落到具体目标用户与持续行为证据，写死失效标志，并由用户明确裁决。

使用者是用户本人及执行选型、调研、评审的 agent。成功不是「文档里出现创新二字」，而是：

1. 无现成社区佐证的新交互可以合法进入候选与实验设计；
2. 实验能够产生可审计的新证据，不再被迫伪造成竞品 issue 缺口；
3. 「卧槽」不能替代行为验证，普通微优化也不能借「创造型」豁免证据；
4. 现行已废除条款与产品裁决不被偷渡恢复。

## 2. 术语与阶段边界

- **候选入场**：允许写入选型卷并做桌面调研；不代表开枪，不授权建仓或编码。
- **创造型伸手实验**：用最低成本把解法放到目标用户面前，观察伸手、复访、留下、掏钱等预定行为。可使用故事板、可点击示意、人工演示或落地页；具体执行及任何对外发布仍须用户另行批准。
- **开枪**：用户明确把候选裁为活跃产品。候选卡、调研、实验设计与实验结果本身都不是开枪。
- **解法重构**：明确写出旧约束 / 旧交互如何被替换，以及因此消失或逆转的步骤；只写「更快、更美、多一个功能」不算。
- **「卧槽」**：创造型的解法质量目标，评价结构重构是否足够非增量；不是灵魂 / 感动的改名，不是需求或付费证据。

## 5. Documentation Style

- 全部使用中文；保留现有历史档案，不为让新指南显得一贯正确而改旧卷。
- 根指南保持**两条心法**，本次修订其内部结构与执行语义，不新增第三套准入标准。
- 规范句必须能落到记录字段或检查动作，避免只写「重视创新」「提升洞察力」。
- 事实、假设、实验结果分栏；所有现象证据保留来源与日期，不编 URL、日期或用户原话。
- 创造型候选卡的最小记录样式：

```markdown
路线：创造型
现象：[日期 + 来源 + 可观察行为]
事实：[已被来源支持的部分]
假设：[尚待验证的部分]
创造链：现象 → 本质 → 什么在变 → 解法重构
结构重构：旧约束 / 旧交互 → 新约束 / 新交互 → 被消除或逆转的步骤
实验预注册：对象 / 接触方式 / 主信号 / 样本分母 / 观察窗口 / 通过线 / 失效线
实验结果：[实际人数与行为，含未伸手者；执行前不填结果]
开枪判断：[证据是否足够 + 用户裁决；不得由 agent 自判开枪]
```

- 补丁型仍使用「谁 / 凑合行为 / ≥3 个独立来源 / 日期分布 / 付费行为单列 / 失效标志」的记录方式。

## 6. Functional Requirements

### R1 · 双路线与默认顺序

根指南必须同时命名创造型与补丁型，明确**默认先尝试创造型**。新选型工作卷须有创造型生成段；允许诚实写「本轮未形成合格创造型候选」，不设数量配额，不为凑数编造现象。

### R2 · 创造型入场证据

创造型候选入场只需具备可核验的现象起点和书面创造链，不要求预先凑齐 ≥3 个社区来源，不要求已有直接竞品或同类付费。个人观察可作假设种子，但不得单独充当开枪证据。没有行为现象的纯想象仍不入场。

### R3 · 补丁型证据不回退

补丁型保留现行标准：≥3 个独立来源、近两年、带日期、行为优先、issue 创建日期分布、付费行为单列。证据强烈时可直接推进，不额外要求「第一次见」「惊艳」或结构颠覆。

### R4 · 创造链与假设诚实

将「推理不许跑到证据前面」修订为：允许假设和推导先于答案，但必须区分事实与假设，不得把未验证推导写成已证实需求。创造链固定为：

`现象 → 本质 → 什么在变 → 解法重构`

写不出结构重构的候选可以退回补丁型审查，不得以创造型名义绕过 R3。

### R5 · 伸手实验预注册

创造型开枪前必须有目标用户行为实验。实验记录至少包含：对象、接触方式、主信号、样本分母、观察窗口、通过线、失效线、结果。通过线与失效线必须在看结果前写下；结果必须报告分母和未伸手者，不得只挑成功反应。

V1 不设全局样本量、复访率或付费转化率数值。具体实验执行、对外发布、接触陌生人或收集信息，须按当时场景另行取得用户批准。

### R6 · 共同开枪闸

开枪前必须同时满足：

- 能指出具体目标用户与使用场景；
- 有持续需求的行为证据：创造型来自伸手实验，补丁型来自正在发生的凑合；
- 失效标志已写死，并保留后续复盘入口；
- 用户明确裁决开枪。

惊叹、掌声、star、下载量、设计者自判「需要」均不能替代上述行为证据。付费仍可作为强行为证据，但不得恢复「形态侧已有付费原话才可开枪」的已废除前置闸。

### R7 · 「卧槽」的正确位置

根指南须明确「卧槽」只约束创造型的解法质量，防止增量微优化冒称创造；它不是独立开枪条件，也不是产品必须通过的普适情感测试。补丁型不因此增加门槛。

### R8 · 深度调研分路线

将根 `CLAUDE.md` 深调研条款改为：

- **公共项**：需求验证、现有替代与邻近付费、定价、系统吸收距离、裁决段、裁决前红队、一页粗算；
- **补丁型专项**：有明确在位者时逐条审查 open issues 及创建日期分布；没有则如实记录；
- **创造型专项**：现象来源与日期、事实 / 假设分列、结构重构说明、伸手实验预注册与结果；
- 没有直接竞品时研究用户当前如何完成任务，不强制伪造竞品矩阵或 issues 清单。

调研三闸（裁决段 / 红队 / 粗算）保持不变。

### R9 · 同步而不扩张

`PRODUCT-DEV-GUIDE.md` 只同步根指南名称、路线术语和必要指针，不将选型实验扩成开工 / 发布新闸。用户级记忆只更新现行摘要与索引，历史段保留并标明不再作为现行口径。

## 7. Boundaries

### Always

- 以已确认意图为边界，保持两条心法与双路线语义一致；
- 保留所有历史候选、历史产品裁决及已废除条款的档案状态；
- 中文文档、来源与日期诚实、事实与假设分离；
- 实施后执行第 8、9 节验收并如实记录未做项。

### Ask first

- 实际执行任何伸手实验、对外发布、联系目标用户或收集数据；
- 复审 round13、复活已埋候选、改变活跃产品或启动 POC；
- 新增全局数值门槛、恢复历史条款、修改本 spec 范围；
- 修改第 4 节以外的文件，或进行 commit / push。

### Never

- 把「卧槽」、掌声或 agent 自信当作需求验证；
- 把创造型路线写成「免需求验证」或把补丁型路线写成「必须颠覆」；
- 为证明指南有效而编造候选、实验结果、来源或日期；
- 修改产品代码、已埋产品状态、`focus-history.json` 数据格式；
- 未获明确指示 commit / push。

## 8. Testing Strategy

本变更无代码测试，采用四层文档验收：

### 8.1 结构检查

- 根指南能检索到两条路线、默认创造优先、实验预注册、共同开枪闸；
- ≥3 来源明确归补丁型，不再被表述为创造型入场前置；
- 「假设可以先于答案，不得冒充事实」取代旧的歧义句；
- 深调研有公共项与分路线专项，无直接竞品时不再强造 issues。

### 8.2 场景回放

| 场景 | 必须得到的结果 |
|---|---|
| 多条近期行为证据显示用户为现有工具缺口写脚本 | 可走补丁型，不要求另造颠覆故事 |
| 有真实现象与原理推演，无 issue、无直接竞品 | 可入创造型并设计实验，不得因缺社区三证直接杀死 |
| 设计者觉得惊艳，实验无人伸手 | 不得开枪，按预注册失效线处理 |
| 有真实现象，但方案只是更快一点 | 可转补丁型，不得借创造型豁免 ≥3 外部证据 |
| 创造型候选暂时没有合格现象，只有漂亮想象 | 不入场，防止以创新名义恢复许愿 |

### 8.3 保持性检查

- 引擎复用仍是默认偏好而非准入；
- 组合纪律、失效标志复盘、发布埋点、30 天校准不变；
- 灵魂论、形态付费前置等历史条款仍处废除状态；
- 已埋 / 暂停产品状态与 round13 候选裁决均未改变。

### 8.4 差异与人工检查

- 运行第 3 节命令，无新增空白错误；
- 审阅根指南最终 diff，确认没有借措辞调整扩大实验授权；
- 由用户在实施后审阅权威条款，确认「创造优先、证据可生成、开枪不降级」三点均被准确表达。

## 9. Success Criteria

- [ ] 根 `CLAUDE.md` 产品心法完成双路线修订，默认创造优先且补丁型合法保留；
- [ ] 创造型无社区三证可入场，但开枪前必须具备实验产生的行为证据；
- [ ] 补丁型 ≥3 来源等原标准完整保留，不附加「必须惊艳」；
- [ ] 创造链包含「解法重构」，事实 / 假设与实验结果可区分、可审计；
- [ ] 伸手实验有预注册字段，且无全局拍脑袋阈值；
- [ ] 深调研按路线执行，无直接竞品时不强制扒不存在的 issues；
- [ ] 「卧槽」被限定为解法质量目标，不是需求、付费或开枪证据；
- [ ] 第 8 节五个场景回放全部得到预期结果；
- [ ] `PRODUCT-DEV-GUIDE.md` 与用户级记忆同步后无现行口径冲突；
- [ ] 未修改任何产品代码 / 状态，未启动实验或 POC，未 commit / push。

## 10. Out of Scope (Deferred)

- 实际生成下一轮创造型候选：指南批准落地后由用户另发任务；
- 用新指南复审 round13 或任何历史候选：避免借流程调整自动复活；
- 统一的实验样本量、复访率、转化率门槛：需真实实验数据后另行校准；
- 实验工具、落地页系统、分析埋点或自动化实现：本 V1 只定义记录契约；
- 修改开工前闸、发布前闸的实质检查项：与本次选型入口问题无关；
- 对历史选型文档做口径清洗：保留当时语境，只更新现行权威源与记忆摘要。

## 11. Open Questions

无阻塞问题。以下默认值已写入本 spec，随 spec 一并批准：

1. 具体伸手实验每次仍需用户批准，不随候选入场自动授权；
2. V1 不设全局实验数值线，按候选预注册；
3. 不回放、不重判任何历史候选；
4. 本 spec 批准后，下一阶段才生成计划与任务清单。
