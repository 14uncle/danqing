## 决策目标

数据同步是旗舰订阅的核心卖点之一(意图: 旗舰订阅 = 场景全开 + 数据同步 + 深度定制), 也是**数据复利在切换侧的放大器**——跨设备后专注历史不丢、多设备各写各的也能汇成一份, 换机/多机续费动机成立。

- **复用十年演进格式**: 同步传输即 `focus-history.json` 的 `FocusHistory` 文档本身, **不新造数据格式**, 不新造版本体系。
- **本地优先**: 单设备可完整离线工作, 同步是增强不是依赖。
- **语义先行**: 本期只把边界、合并语义、订阅归属写清楚; 后端选型与实现是独立任务。

## 核心原则

1. **数据层免费不变**: 本地收集/统计/导出免费(见定价 spec); 同步是"把数据送上天"才收费。不上云的数据照常全量收集。
2. **记录不可变**: 会话追加式、无编辑、无删除(本期)→ **同步无冲突类**, 合并 = union, 不需要 LWW / CRDT。
3. **降级保护同构**: 同步版本阶梯镜像本地 `refuse_overwrite`——旧端不写新数据, 新数据不被旧端覆盖。
4. **设置不跨设备**: 设备本地偏好(计时方案/场景/音景/今日计数)不同步, 避开可变状态的合并复杂度。

## 同步范围

| 内容 | 是否同步 | 理由 |
|------|---------|------|
| `focus-history.json` 的 `sessions`(专注会话历史) | **同步(全量)** | 数据护城河本体, 跨设备价值的核心 |
| 设置 `pomodoro.json`(计时方案/场景偏好/音景开关) | **不同步** | 设备本地偏好; 可变状态需 LWW 合并, 复杂度与价值不成比例 |
| 今日计数(`today_date`/`today_count`) | **不同步** | 按本地日期归零的运行态, 跨时区/跨设备语义不清; 将来可由同步后的 sessions 派生 |
| 场景/主题/音频资产 | **不同步** | 随应用版本分发, 不走数据同步 |

**非订阅用户的搬移兜底**: 数据导出(CSV/JSON 明文)已免费——任何人可手动搬移历史。付费买的是「自动 + 多设备」, 不是「数据所有权」。

## 数据格式复用

- **传输文档** = 现有 `FocusHistory` JSON(顶层 `format_version` + `sessions` 数组), 字段原样传输, 不做变换、不做裁剪。
- **同步信封**(传输元数据, 不入库): `{ format_version, device_id, sync_ts }` —— 用于版本校验与对账。云端副本仍是纯 `FocusHistory`。
- **前置格式演进(已裁定)**: `SessionRecord` 增加 `session_id: String`(UUIDv4), `#[serde(default)]` 空串 → **`format_version` 保持 1**, 旧文件可读、旧程序可读。同步以 `session_id` 为去重键; 旧记录(空 session_id)按 `(started_ts, completed_ts)` 兜底去重。
- **device_id(已裁定)**: 首次同步生成并持久化, 标识来源设备; v1 仅作诊断与对账, 未来增量同步游标的前置字段。

> 为什么现在不改代码: Task H 范围是 S(仅 spec)。`session_id` 无同步消费者时是无用字段; 去重兜底键已覆盖过渡期, 字段留待同步真正开工时加。

## 合并与去重语义

- **数据模型**: 每条记录不可变、追加式、全局无编辑/无删除 → **同步无冲突类**, 不需要冲突解决算法。
- **合并**: `merge(A, B) = A ∪ B`——按 `session_id` 去重(旧记录按 `(started_ts, completed_ts)`), 不删除任一侧已有记录。
- **对账模型**(中心账本, 每用户一份云端 `FocusHistory`):
  1. **上行**: 本地有、云端没有的记录推给云端; 云端按 `session_id` 去重并入用户副本。
  2. **下行**: 拉取云端全量; 本地按 `session_id` 并入自己文件, 不删自己的记录。
- **幂等**: 重复同步无害(union 天然幂等), 支持任意顺序、任意次数。
- **全量对账即可**(v1 语义); 增量(游标/分页)是实现优化, 非语义要求。
- **删除**: 本期无删除语义。将来若加「删除会话」, 须引入墓碑(tombstone)——列为未来工作, 不在本期设计。

## 版本边界

- 发送方消息携带 `format_version`(文档自身也已带)。
- **接收方规则**(镜像本地 `refuse_overwrite`):
  - `接收方版本 == 消息版本` → 正常合并
  - `接收方版本 < 消息版本` → **拒收不落盘、提示升级**(防降级覆盖新数据)
  - 云端同规则: 云端副本版本更高时, 旧端**只读不写**。
- 字段级演进(serde default)不动 `format_version`; 只有大版本提升才触发阶梯。

## 已定决策(2026-08-02 用户裁定)

1. **同步范围仅 `sessions`** —— 设置/今日计数/资产不同步; 数据导出免费是任何用户的搬移兜底。
2. **`session_id` 同步开工时再加** —— 本 spec 定为前置演进(向后兼容, format_version 保持 1), 但 Task H 不动代码; 字段与测试随同步实现落地。
3. **订阅专属** —— 数据同步不在买断 ¥68 内(买断 = 全 5 场景 + 环境音); 与年度报告同属订阅留口, 本期不上线、不做展示。
4. **全量对账即可** —— 增量(游标/分页)是实现优化, 非语义要求。
5. **合并去重键 = `session_id`(UUID)** —— 旧记录(空 session_id)按 `(started_ts, completed_ts)` 兜底。
