丹青番茄钟场景动效的机制选择教训(2026-07-29 海场景终审,用户裁定):

- **亮度/颜色调制(additive 或乘性)作用于静态图之上,人眼读作"明暗对象沿静态背景移动"——像车在波形路上开,路本身没动**。加码幅度(±4%→±35%)不能补救,机制错了。
- **要让"背景图本身在动",必须动采样坐标**: UV 位移扭曲(`sample_uv.y = uv.y + swell(uv,t) × intensity`),剪影边缘随之起伏。位移须随效果强度缩放,暂停沉降才能逐像素回静态(暗启动纪律)。
- 位移场设计: 天空区 mask 为 0 不动、越靠下(近水)位移越大(透视感)、相位含小 y 项使波峰不成直线、两层同向行进(反向叠加成驻波,原地脉动读不出"动")、频率全落 1/8 Hz 整数倍保 8s 公共周期。
- **亮场景(近白底)additive 光点会被底吃掉,细碎提亮元素走乘性**;暗场景(篝火)additive 可读。
- 用户主导的方向修正(指定数值/裁定换机制)不计入"调参 ≤2 轮"撤退预算——同篝火"用户指定 7px"先例。

**2026-07-29 雨场景修订(重要例外)**: **UV 位移对"沿自身轴向均匀"的元素不成立**——画中雨丝沿下落方向近乎平移不变,沿线滑动(摆动 ±5px 或流图持续滑落)除丝头外无可读变化,用户目测"底层静态背景图的雨没有动"。两版机制(正弦剪切、双相位流图)试错后,用户裁定更干净的方向:**静态图去烘焙丝 + 运行时全程序化渲染**(雨幕独挑 ~290 丝),并追加"暂停显示雨丝"→ 雨钟定格(强度去包络,包络只推进下落时间)。

**Why**: 海场景三轮调参证明幅度救不了错误机制,换 UV 位移一轮通过;雨场景又证明 UV 位移有适用边界——它动的是"剪影/形状",对沿轴均匀的线条无棱可动。

**How to apply**: 场景动效机制选型先看元素几何: 有剪影边缘可动(波带/山脊/树冠)→ UV 位移;沿轴均匀线条(雨丝)或点状粒子(余烬/碎点)→ 去烘焙 + 程序化渲染。篝火(余烬点 + 光晕)按后者再议。相关: [[danqing-project-state]]
